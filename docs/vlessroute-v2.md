# VLESS 路由线路（V2）

状态：已实现并完成本地验收（2026-10-16），待管理员人工体验反馈。基于 `main` 的独立实现，不恢复已废弃 V1 的服务端网络管理页。本文记录的是有界功能验收，不扩大全局后端兼容矩阵的支持承诺。

## 已确定的交互与兼容语义

- 节点编辑原中转区域改为“中转线路 / VLESS 路由线路”两个标签页，仍使用同一保存按钮。控件格式、卡片边框、间距、字号及位置沿用中转线路：标题左侧、添加按钮右侧；卡片首排依次为名称、启用、上移、下移、删除，下一排并排选择线路入口和线路出站，各占一半。路由已确认应用且详情读取正常时显示绿色确认提示，提醒实际流量仍需测试；不显示 route 数值标签，异常和失败提示保留。
- 3X-UI 负责出站配置，PSP 只读取已有模板及订阅出站标签，不创建或改写出站。
- “按节点选择”继续引用 NodeID，动态包含其全部可发布直连线路、中转线路及 VLESS 路由线路；新增“按线路选择”精确引用 `node_id + line_id`。
- 历史中转补充持久化 ID，原代理组数据无需转换；没有新配置时，原订阅结果不变。新增 VLESS 路由线路自动加入已选择父节点的代理组。
- 每条 VLESS 路由线路可选择直连或一个已保存的中转入口，按稳定中转 ID 引用，不自动交叉展开；候选仅显示中转线路自身名称，不带 `[中转]`，直连候选显示“直连”。缺省依赖直连；直连隐藏或选中中转停用/删除时保留配置但实际不可用、不发布，不回退其他入口。
- 每条中转线路和 VLESS 路由线路提供独立的“仅显示线路名称”开关（`only_line_name`）。默认关闭，旧数据缺少字段时同样为 `false`：关闭时使用“节点名称 + 线路名称”，开启时只使用线路名称；无名称中转仍以入口地址回退。此选项只控制代理名，不改变线路 ID、入口、出站或凭据。重名继续沿用已有去重后缀。
- 三种订阅格式及代理组成员预览共用线路命名规则。自动添加区域国旗仍由原有逻辑按父节点 `region` 处理，不受本开关影响；国旗关闭时不额外添加。
- 功能仅用于 3X-UI 的 VLESS 节点，不以面板或内核的具体版本号限制使用。取消版本限制不代表已验证所有版本的兼容性。
- 路由名称可留空，动态使用所选出站标签作为名称；“仅显示线路名称”开启时同样适用。中转状态自动探测并显示所有启用线路，停用线路不探测、不展示缓存状态；旧 `show_relay_status` 存储字段仅作兼容保留，不再影响行为，也不提供编辑开关。
- 用户“服务器状态”页同时显示可发布的 VLESS 路由线路，两类派生线路均遵循各自 `only_line_name`，缺省仍带节点名前缀。路由复用所选直连/中转入口的状态及检查时间，不新增探测；该状态仅表示入口可达，不表示线路出站可用。接口不提供凭据、入口地址/端口或内部故障详情，未命名中转继续用本地化序号，不把入口地址当作状态名称。

## 路由与凭据

功能名称统一为“VLESS 路由线路”；代码标识符、接口路径和 Xray 原生 `vlessRoute` 字段保持不变，不能将显示名称写入协议配置。

PSP 每条线路维护一条 `inboundTag + vlessRoute -> outboundTag` 规则，适用于该入站所有用户，不额外创建 client 或真实 inbound。订阅使用已应用凭据，只改变 UUID 第 7、8 字节；直连线路 UUID 不变。

每条线路提供默认收起的“高级路由规则”，仅含五个可选字段：网络、协议、IP、域名和端口，直接附加到该线路原有规则，不增加规则列表、条件规则 ID、单独出站或兜底规则。网络可选 TCP、UDP 或不限；协议多选 http/tls/quic/bittorrent（入站嗅探结果，不是 VLESS 代理协议）；IP/域名每行一项，端口支持逗号与范围（1–65535）。IP/端口均指目标而非线路入口。

五项留空保持旧行为；已填写的不同字段必须同时满足，并继续受原 `inboundTag + vlessRoute` 限制。未匹配时继续执行后续服务端规则，最终可能使用内核默认出站，**不保证走本线路的线路出站，也不自动补兜底**。PSP 不修改全局 DNS/domainStrategy 或入站嗅探；协议匹配须由管理员在 3X-UI 启用对应嗅探，IP/域名匹配依赖实际可见地址、DNS 策略和已有 geoip/geosite/ext 资源。前置自定义规则仍优先。

五项作为线路 JSON 的可选 `network`、`protocols`、`ip`、`domain`、`port` 存储，缺失/空值等价；编译为原生 network/protocol/ip/domain/port，空条件不下发。无需数据库迁移，不改变 route 数值、ruleTag、订阅条目数或凭据。所有条件参与同步回读及漂移检测；清空条件恢复原规则，启停/删除仍只维护这同一条登记规则。

折叠/展开只控制显示，不清除或停用已保存的条件；保存仍使用线路现有保存流程及最新写响应。刷新保护这些未保存字段，其他写入者改变条件时沿用原 CAS 冲突保护。

规则只维护登记拥有的 `ruleTag`，追加到用户规则之后，保留其他字段与出站配置。Xray 首次命中即停止，因此前置自定义规则优先；前置兜底可使新规则永不生效。`IPIfNonMatch` 可能因末尾规则首次遍历已命中而不触发第二轮 DNS/IP 匹配。VLESS 路由线路不是授权隔离，持有原凭据的客户端可自行改变 route 值。

保存即同步，后台记录目标和结果、回读确认后发布；不提供独立草稿或应用页面。3X-UI 使用整模板更新且没有 CAS，PSP 内部按后端租约串行并检查写前变化，但不能保证消除外部并发写入；应用窗口须单写模板。更新可能重载或重启内核。

停用或删除撤下订阅并移除规则，不保留阻断规则，也不吊销已下载凭据。旧配置仍可能通过认证，然后按其他规则选路。同一节点内退役 ID/route 值不重新分配；这不是跨节点生命周期的凭据撤销机制。

## 操作流程

1. 在 3X-UI 配置并验证目标出站。PSP 不提供出站编辑器；不要依靠新增线路来修复失效的出站。
2. 在 PSP 节点管理打开已有 VLESS 节点的“编辑节点”，切换至“VLESS 路由线路”标签。
3. 进入标签页时立即只读校验远端路由；右上角刷新按钮同时重新校验状态及读取已有出站。添加线路，选择线路入口和出站标签，名称可选。默认入口为直连；新增未保存的中转入口需先保存节点，再按其稳定 ID 选择。每个节点最多保留 64 条未删除线路，可独立启停、排序和删除。
4. 使用原有“确定”按钮直接保存并同步，不再弹出额外同步确认。更新仍可能重载或重启内核，应用期间不要同时编辑服务端模板；仅修改普通节点元数据不必重写路由。
5. 只有 `applied` 表示模板回读和内核运行已确认，不表示所有目标流量已经实测可达。`applying`、`unknown`、`drift` 都不发布派生线路；结果未知时保留对话框供核对，不能自动重复提交。
6. 在规则库编辑代理组成员，选择“按节点选择”加入动态全集，或选择“按线路选择”，先选节点、再选该节点下的一条线路；保存规则集后由实际用户订阅验证。

“直连线路”指客户端直接连接节点入口、未经中转线路的访问方式，不代表强制使用服务端 freedom/direct 出站。直连线路 A 的出站仍由 3X-UI 现有规则与默认出站决定。需要 A 使用 direct 出站、B 阻断时，应先确认 A 的实际出站，再将 B 指向既有 blackhole 出站；PSP 不会替管理员改写 A 的规则。已有兜底规则可能使 B 永远无法命中，须由管理员自行调整既有规则，PSP 不自动提权新规则。

“隐藏直连线路”同时使依赖直连的 VLESS 路由线路实际不可用；依赖启用中转的路由不受影响。配置开关保留管理员启用意图，入口恢复后可重新生效；不可用期间编辑器显示未启用，规则候选标为不可用，代理组预览、三种订阅格式和前台状态页均不发布。该本地发布约束不会撤销已下载凭据，不因隐藏/停用入口自动改写远端路由模板；原有自定义规则与已下载配置的授权边界不变。所有线路仍受父节点启用状态、用户分组访问范围与已确认凭据约束。

### 精确引用与旧数据

```yaml
proxy_group_members:
  Entire-Node:
    - kind: node
      node_id: 7
  Only-Direct:
    - kind: line
      node_id: 7
      line_id: direct
  Only-One-Line:
    - kind: line
      node_id: 7
      line_id: <从候选目录取得的稳定线路ID>
```

旧 `kind: node` 数据不迁移：未来新增中转线路或 VLESS 路由线路自动加入。`kind: line` 不按名称、地址或排序定位，重命名不会改变引用，后续新增线路不会加入。同时选择节点及其单条线路时，按最终条目去重并保持首次出现顺序。删除引用保留失效告警，不静默替换为另一条线路。

“按线路选择”的原候选区域拆为两个等宽下拉框：左侧列出全部节点，右侧仅列出所选节点的全部线路。未选节点时右侧禁用，切换或清空节点会清空线路选择及搜索文字；添加后保留节点，方便连续添加同一节点下的其他线路。候选显示线路自身名称和短类型，例如 `my-relay-line [中转]`、`my-vlessroute-line [VLESS 路由]`，直连线路只显示 `[直连线路]`，不重复节点名称；不可发布状态另行提示。已添加成员和订阅使用遵循“仅显示线路名称”开关的统一线路显示名，保存结构仍为 `node_id + line_id`。

成员卡片只显示成员名称，不再内联显示标识；悬停或键盘聚焦名称时，在上方浮层显示完整标识。悬停范围及浮层锚点仅覆盖名称标签，不占满整行；名称保持单行，长名称省略显示。添加成员的全部分类均显示对应说明，包括动态加入、订阅范围、代理组引用限制及 Rematch 的客户端兼容性，不改变成员解析语义。

候选接口增加只读 `name` 字段用于线路自身名称，原 `display_name` 继续表示完整订阅显示名；前端对旧响应缺失 `name` 时回退到完整名，不从父节点字符串中猜测、截断线路名称。没有数据库或旧规则成员数据迁移。

历史中转只回填持久化 ID，不改连接字段。升级前备份数据库；回退应恢复对应数据库及配置快照，不能把“旧二进制能启动”当成数据回退验证。

### 故障处理

- 出站目录读取失败不是空目录；核对连接、后端版本和权限后重读。
- 出站被外部删除、PSP 规则被修改或不再位于末尾、后端绑定变化时，只读检查撤下本地派生线路，不自动覆盖用户模板。周期检查存在检测窗口，并非实时阻断。
- 同一模板应用窗口内不要同时在 3X-UI 修改配置。冲突时重读最新状态，不能拿旧 revision 强行覆盖。
- 节点删除、解绑、重建及端口/协议变更前会清理其登记规则；清理未确认时停止后续破坏性步骤，保留可重试状态，不跳过远端清理失败。
- 多步骤保存中普通资料成功、路由未知，不意味着整次操作未发生；页面保留已成功字段和最新路由 revision，避免重新读旧列表或重复写入。

接口包括 `GET/PUT /api/admin/nodes/:id/vless-route-lines` 和管理员专用的 `GET /api/admin/nodes/:id/vless-route-outbounds`；代理组检查增加无凭据的 `lines` 候选目录，成员新增 `kind: line`。读取失败不是空列表；远端未知、漂移或绑定变更时，新线路不得被当作已确认发布。

线路 `GET` 对已有登记线路立即执行单节点远端只读校验，再返回最新本地状态；校验结果变化会更新本地 revision 并失效订阅缓存，不写入远端模板。显式刷新遇到后端租约忙时返回冲突，不把未校验的旧成功状态当作新结果；后台定时巡检保持原有跳过忙后端的行为。无线路登记时不伪造 `applied` 状态。

`PUT` 提交 `{ revision, lines: [{ id?, name?, entry_relay_id?, outbound_tag, enabled, only_line_name?, network?, protocols?, ip?, domain?, port? }] }`，返回含最新 revision、实际目标与同步状态的安全视图。名称缺省或留空时使用出站标签；`entry_relay_id` 缺省或空字符串表示直连入口，非空时引用该节点的稳定中转 ID。已有线路必须携带原 ID，新线路省略 ID；删除通过省略该线路表达。`only_line_name` 缺省为 `false`，中转线路元数据接口使用同名字段；两类线路均在既有 JSON 数据中持久化，不需要数据库迁移。读取线路沿用 staff 节点读权限，读取出站和写入仅限管理员，并继续执行强制二次认证准入。候选目录只暴露 tag/protocol/source，不回显完整出站配置或凭据。

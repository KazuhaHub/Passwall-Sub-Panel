# VLESS 路由线路（V2）

状态：已实现并完成本地验收（2026-10-16），待管理员人工体验反馈。基于 `main` 的独立实现，不恢复已废弃 V1 的服务端网络管理页。本文记录的是有界功能验收，不扩大全局后端兼容矩阵的支持承诺。

## 已确定的交互与兼容语义

- 节点编辑原中转区域改为“中转线路 / VLESS 路由线路”两个标签页，仍使用同一保存按钮。控件格式、卡片边框、间距、字号及位置沿用中转线路：标题左侧、添加按钮右侧；卡片首排依次为名称、启用、上移、下移、删除，出站选择独占下一排。不显示成功确认横幅或 route 数值标签，异常和失败提示保留。
- 3X-UI 负责出站配置，PSP 只读取已有模板及订阅出站标签，不创建或改写出站。
- “按节点选择”继续引用 NodeID，动态包含其全部可发布直连线路、中转线路及 VLESS 路由线路；新增“按线路选择”精确引用 `node_id + line_id`。
- 历史中转补充持久化 ID，原代理组数据无需转换；没有新配置时，原订阅结果不变。新增 VLESS 路由线路自动加入已选择父节点的代理组。
- VLESS 路由线路只继承原入口，不与中转组合；隐藏原入口生效时也不发布 VLESS 路由线路。
- 功能仅用于 3X-UI 的 VLESS 节点，不以面板或内核的具体版本号限制使用。取消版本限制不代表已验证所有版本的兼容性。

## 路由与凭据

功能名称统一为“VLESS 路由线路”；代码标识符、接口路径和 Xray 原生 `vlessRoute` 字段保持不变，不能将显示名称写入协议配置。

PSP 每条线路维护一条 `inboundTag + vlessRoute -> outboundTag` 规则，适用于该入站所有用户，不额外创建 client 或真实 inbound。订阅使用已应用凭据，只改变 UUID 第 7、8 字节；直连线路 UUID 不变。

规则只维护登记拥有的 `ruleTag`，追加到用户规则之后，保留其他字段与出站配置。Xray 首次命中即停止，因此前置自定义规则优先；前置兜底可使新规则永不生效。`IPIfNonMatch` 可能因末尾规则首次遍历已命中而不触发第二轮 DNS/IP 匹配。VLESS 路由线路不是授权隔离，持有原凭据的客户端可自行改变 route 值。

保存即同步，后台记录目标和结果、回读确认后发布；不提供独立草稿或应用页面。3X-UI 使用整模板更新且没有 CAS，PSP 内部按后端租约串行并检查写前变化，但不能保证消除外部并发写入；应用窗口须单写模板。更新可能重载或重启内核。

停用或删除撤下订阅并移除规则，不保留阻断规则，也不吊销已下载凭据。旧配置仍可能通过认证，然后按其他规则选路。同一节点内退役 ID/route 值不重新分配；这不是跨节点生命周期的凭据撤销机制。

## 操作流程

1. 在 3X-UI 配置并验证目标出站。PSP 不提供出站编辑器；不要依靠新增线路来修复失效的出站。
2. 在 PSP 节点管理打开已有 VLESS 节点的“编辑节点”，切换至“VLESS 路由线路”标签。
3. 刷新已有出站，添加线路，填写名称并选择出站标签。每个节点最多保留 64 条未删除线路，可独立启停、排序和删除。
4. 使用原有“确定”按钮直接保存并同步，不再弹出额外同步确认。更新仍可能重载或重启内核，应用期间不要同时编辑服务端模板；仅修改普通节点元数据不必重写路由。
5. 只有 `applied` 表示模板回读和内核运行已确认，不表示所有目标流量已经实测可达。`applying`、`unknown`、`drift` 都不发布派生线路；结果未知时保留对话框供核对，不能自动重复提交。
6. 在规则库编辑代理组成员，选择“按节点选择”加入动态全集，或选择“按线路选择”，先选节点、再选该节点下的一条线路；保存规则集后由实际用户订阅验证。

“直连线路”指客户端直接连接节点入口、未经中转线路的访问方式，不代表强制使用服务端 freedom/direct 出站。直连线路 A 的出站仍由 3X-UI 现有规则与默认出站决定。需要 A 使用 direct 出站、B 阻断时，应先确认 A 的实际出站，再将 B 指向既有 blackhole 出站；PSP 不会替管理员改写 A 的规则。已有兜底规则可能使 B 永远无法命中，须由管理员自行调整既有规则，PSP 不自动提权新规则。

隐藏原入口仅在存在启用中转时生效，沿用旧行为；此时 VLESS 路由线路也不发布，防止派生条目重新暴露原入口。所有线路仍受父节点启用状态、用户分组访问范围与已确认凭据约束。

### 精确引用与旧数据

```yaml
proxy_group_members:
  Entire-Node:
    - kind: node
      node_id: 7
  Only-Direct:
    - kind: line
      node_id: 7
      line_id: direct
  Only-One-Line:
    - kind: line
      node_id: 7
      line_id: <从候选目录取得的稳定线路ID>
```

旧 `kind: node` 数据不迁移：未来新增中转线路或 VLESS 路由线路自动加入。`kind: line` 不按名称、地址或排序定位，重命名不会改变引用，后续新增线路不会加入。同时选择节点及其单条线路时，按最终条目去重并保持首次出现顺序。删除引用保留失效告警，不静默替换为另一条线路。

“按线路选择”的原候选区域拆为两个等宽下拉框：左侧列出全部节点，右侧仅列出所选节点的全部线路。未选节点时右侧禁用，切换或清空节点会清空线路选择及搜索文字；添加后保留节点，方便连续添加同一节点下的其他线路。候选显示线路自身名称和短类型，例如 `my-relay-line [中转]`、`my-vlessroute-line [VLESS 路由]`，直连线路只显示 `[直连线路]`，不重复节点名称；不可发布状态另行提示。已添加成员和订阅继续使用完整显示名，保存结构仍为 `node_id + line_id`。

成员卡片只显示成员名称，不再内联显示标识；悬停或键盘聚焦名称时，在上方浮层显示完整标识。悬停范围及浮层锚点仅覆盖名称标签，不占满整行；名称保持单行，长名称省略显示。添加成员的全部分类均显示对应说明，包括动态加入、订阅范围、代理组引用限制及 Rematch 的客户端兼容性，不改变成员解析语义。

候选接口增加只读 `name` 字段用于线路自身名称，原 `display_name` 继续表示完整订阅显示名；前端对旧响应缺失 `name` 时回退到完整名，不从父节点字符串中猜测、截断线路名称。没有数据库或旧规则成员数据迁移。

历史中转只回填持久化 ID，不改连接字段。升级前备份数据库；回退应恢复对应数据库及配置快照，不能把“旧二进制能启动”当成数据回退验证。

### 故障处理

- 出站目录读取失败不是空目录；核对连接、后端版本和权限后重读。
- 出站被外部删除、PSP 规则被修改或不再位于末尾、后端绑定变化时，只读检查撤下本地派生线路，不自动覆盖用户模板。周期检查存在检测窗口，并非实时阻断。
- 同一模板应用窗口内不要同时在 3X-UI 修改配置。冲突时重读最新状态，不能拿旧 revision 强行覆盖。
- 节点删除、解绑、重建及端口/协议变更前会清理其登记规则；清理未确认时停止后续破坏性步骤，保留可重试状态，不跳过远端清理失败。
- 多步骤保存中普通资料成功、路由未知，不意味着整次操作未发生；页面保留已成功字段和最新路由 revision，避免重新读旧列表或重复写入。

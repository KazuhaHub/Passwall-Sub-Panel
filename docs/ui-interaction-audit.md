## 0. 跨页面的共性问题

六个页面里反复出现同样的几类问题，适合用共享构件一次解决：

| 问题 | 出现在 | 统一做法 |
| --- | --- | --- |
| 新建一套界面、编辑另一套 | 节点、服务器、用户 | 新建向导与详情页共用同一批表单 |
| 一行上堆很多图标按钮 | 节点、服务器（7 个以上）、用户 | 行内只留"打开"和"更多" |
| 对话框里再开对话框或抽屉 | 服务器、用户、设置、风险中心、访问控制 | 复杂对象改成详情页，标签代替嵌套 |
| 类型靠下拉框选，字段悄悄变化 | 节点线路、服务器类型、重装目标 | 带小图的选项卡片 |
| 状态是一行行小字或并排徽章 | 全部 | 一个状态点；异常才出彩色标签和原因 |
| 同一个东西多个叫法 | 全部 | 一张术语表（见第 7 节），全站统一 |
| 值来自哪一层看不出来 | 用户额度、分组覆盖、设置的适用对象 | "全局 → 分组 → 本人"三格，生效的一格高亮 |
| 一个保存按钮管多件事，或一屏多个保存 | 设置、用户编辑、分组 | 每个分区或标签单独保存，吸附保存条只管当前分区 |
| 要重启或异步生效，但界面没说 | 设置、服务器内核选择 | 字段旁明确标注 |

## 1. 设置页（`SettingsView.tsx`，3078 行）

### 现状

8 个一级标签（:448–457）：登录与安全、基本设置、站点品牌、订阅管理、用户门户、邮件提醒、SSO 认证、隐私与协议。前两个各有约 45 个字段。保存按钮有 6 套以上：全局吸附栏（:465，管 6 个标签）、分组覆盖栏（:552）、邮件栏、邮件模板单独保存、SAML 栏、OIDC 栏，外加探测设置自己的保存。

### 问题

- **无关内容放在一起。** "登录安全"一张卡约 320 行（:606–923），装着验证码、锁定、找回密码、自助注册、两步验证。"运行时调度"（:946–1012）混着时区、采集周期、四种日志保留天数、邮件提醒阈值。
- **放错地方的设置。** "允许用户编辑个人规则"在登录区（:594）；订阅限流在"登录与安全"（:937）；紧急访问在"基本设置"；Cloudflare 地址段（:1055）、原生任务生命周期（:1014）、链路探测是节点的事。
- **保存有副作用。** "立即更新 IP 库"会先保存整页设置（:243，已核对）。SAML 的"获取并校验"会顺手保存整份 SAML 配置（:2580）。
- **"取消"会丢数据。** 它实际是重新拉取，丢掉整页未保存修改，没有确认（:472，已核对）。
- **要重启的设置没有提示。** 流量采集间隔改了要重启才生效，旁边的核对间隔却即时生效；界面文案里没有任何区分（已核对语言文件）。
- **适用对象栏让字段凭空消失。** 切到某个分组后整个表单换成覆盖编辑器（:543），只能全局设置的字段不见了，没有说明。
- **一件事跨两处。** 登录模式在安全标签，SSO 开关在 SSO 标签。登录模式下拉（:578）和"禁止用户本地登录"开关（:586）如何组合，页面没说（是否冲突属推断）。
- **同一个地址三种叫法**：订阅 Base URL、订阅基础 URL、公网基地址。
- **整份提交可能覆盖别处的修改（未核对，需要专门验证）。** 设置对象整体提交，草稿只在首次加载时写入（:305）。在别的页面改了同一份设置里的字段，再回到设置页用旧草稿保存，可能把那边的修改盖掉。这一条如果成立是数据问题，不只是交互问题。

### 新结构

左侧分区导航 + 设置项搜索，每区单独保存：

1. 站点与访问地址（文案、Logo、主题色、面板公网地址、路径前缀、时区）
2. 登录方式（登录模式、SAML、OIDC 各为子页）
3. 账号安全（验证码、锁定、两步验证、令牌有效期）
4. 注册与找回
5. 订阅（含订阅限流、订阅日志保留）
6. 用户权益（紧急访问、个人规则开关）
7. 通知（SMTP、提醒阈值、模板）
8. 用户门户
9. 隐私与协议
10. 数据保留（所有保留天数集中成一张表）
11. IP 地区库
12. 后台任务（标注哪些要重启）

移出设置页：Cloudflare 地址段、原生任务生命周期、链路探测，放到节点或服务器相关页面。

### 图示

- 登录模式：用户 → 登录页 → 本地 / SSO / 自动跳转 → 面板，每种模式标出显示哪些入口。
- SSO 规则匹配：身份提供方属性 → 第一条命中的角色规则 → 第一条命中的分组规则 → 否则默认组。
- 面板公网地址被谁使用：SAML、通行密钥、邮件链接、订阅链接。改它会影响谁，一张图说清。

## 2. 服务器页（`ServersView.tsx`，2785 行）

### 现状

一张表 + 十来个浮层挂在同一个文件里（1786–2115，已核对）。每行多个图标按钮，另有"更多"菜单。版本格最多叠五层信息（1103–1263），状态格叠三层（1642–1644）。

### 问题

- **三种服务器共用一张表单。** 类型是下拉框（1924–1947），切换时悄悄清空字段（1931–1941）。默认类型是 Passwall Node（:175，已核对），而它的新建实际是"建记录 + 装 Agent"两步。
- **安装流程塞在新建对话框里。** 创建后同一个对话框原地换成安装页（1917）。"升级"和"换身份"是两个互斥复选框（2502–2512），选错要到主机上才报错。命令会过期，没有倒计时。
- **升级入口分散，同一位置行为不同。** 3X-UI 的升级是连环确认框（441 → 461 → 505 → 550）。Passwall Node 的"选择内核"只记录意图、异步生效，3X-UI 的"升级 Xray"立即执行，两者占同一个菜单位置（1771）。
- **"重装 / 换后端"是一个下拉框，选完跳去别的对话框**（`ReinstallBackendDialog.tsx`）。迁移对话框沿用同一个标题（`NodeMigrationPreviewDialog.tsx:233`），用户分不清自己在哪一步。
- **3X-UI → Passwall Node 迁移有 5 步，全挤在一个对话框**（236–296）。
- **能力差异靠隐藏。** 某种服务器没有的功能，按钮直接不出现，用户不知道为什么。
- **占用看不到。** 删除被节点占用的服务器时才弹"有节点"对话框，事先看不到节点数。
- **同一台机器至少五种叫法**：服务器、面板、后端、节点、Agent。

### 新结构

列表 + 服务器详情页（`/admin/servers/:id`）。

- 列表列：名称（带类型图标）、地区、状态点、版本（有更新时一个箭头）、节点数。行内只留"测试"和"更多"。
- 详情页标签：概览、安装与升级（按类型显示内容）、共用端口（仅 Passwall Node）、访问控制（仅 Passwall Node）、指标与诊断、设置（含危险区）。
- 不支持的能力显示为灰色并说明原因，不隐藏。
- 新建改成向导：选类型（三张带图卡片）→ 填字段 → 安装（仅 Passwall Node）→ 等待上线。
- 迁移做成独立向导：预检 → 处理问题 → 选版本 → 确认 → 复制命令 → 等待切换。

### 图示

- **接入方式**（选类型卡片和详情页顶部）：PSP → 3X-UI（调用 API）；PSP → S-UI（调用 API，仅 Token）；Passwall Node ⇢ PSP（Agent 主动连回）。一眼看出方向不同。
- **安装握手**：PSP 生成命令（带倒计时）→ 管理员在主机执行 → 主机下载并校验 → Agent 连回 → 在线。当前步高亮。
- **迁移路径**：标出"保留的"和"会变化的"。
- **SNI 共用端口**：客户端 → 公网端口 → 按域名匹配 → 各监听 / 转发；未匹配 → 默认目标。现在是文字加箭头（`SharedPortsDialog.tsx:117–129`），数据已有。

## 3. 用户页与分组页

### 现状

用户页（`UsersView.tsx`，2379 行）：11 列表格；行内 4 个图标 + "更多"；9 类浮层，包括 860px 的编辑对话框、账号安全抽屉、风控抽屉。分组页（`GroupsView.tsx`）：一个 600px 对话框，内含 4 个标签。

### 问题

- **两条停用轴看着像一条。** 列表并排两个徽章"账户正常""代理服务正常"（:1302）。账户停用时服务徽章显示"代理服务不可用"（:1297），像是第二个故障。
- **两条轴的操作不对等。** 列表里停用账户要填原因（:845）。暂停代理服务点了立即生效，原因写死，没有确认（:1084，已核对）。编辑框里账户状态是下拉框、等"确定"才生效，服务状态却是旁边的即时按钮（:2062、:2081–2092）。
- **同一个输入框，"0"的意思不同（已核对）。** 新建时流量上限填 0，后端当作"跟随分组"（`internal/domain/limits.go:118`）；编辑时 0 是"明确不限量"，旁边另有"跟随分组"开关（:2125）。两处用同一个标签，写着"0 = 无限"。
- **一个用户能叠三层浮层**：编辑对话框 → 风控抽屉；更多 → 账号安全抽屉 → 重置密码 → 结果。
- **保存是三次串行请求**，中途失败只能重新加载（:804–815）。
- **合力看不见。** 状态徽章只显示优先级最高的一个原因；过期又超额的用户只看得到一项。流量重置周期没有"下次重置日"。
- **"本周期已用"是可编辑输入**（:2147），和只读用量条同屏，意图相反。
- **列表用量只对榜上用户有值**（:1369），其余显示"—"（边界属推断）。
- **批量操作只管账户轴**（:1433–1479），没有服务轴。
- **运营角色的限制靠隐形**：看不到某些行的按钮，但页面没有说明"你只能管理普通用户"。
- **分组的策略在列表里看不到**；"成员"标签只是一句话（:920）。

### 新结构

用户：列表 + 详情页（`/admin/users/:id`）。

- 列表：用户、分组、**一个访问状态点**（异常才出标签和原因）、用量与到期合成一列、最近活跃。筛选增加状态、角色、风控。
- 详情顶部是"能不能连上"的判断链，下面分标签：概览、额度与期限（每项标来源）、账号（并入账号安全）、订阅与规则、风控与活动。
- "面板登录"和"订阅与代理"做成同一区域里的两个开关，各自带原因和确认。

分组：列表 + 详情页，标签为节点、成员（直接列出用户）、额度与安全、覆盖、目的地，各自保存。列表加一列策略摘要。

### 图示

- **"为什么连不上"链**：能登录 → 未封号 → 服务未暂停 → 紧急访问 → 未过期 → 额度未用尽 → 分组里有可见节点 → 可连接。卡在哪一环就在哪一环标红并写原因。优先级顺序取自 `internal/domain/access.go`。
- **值的来源**：全局 → 分组 → 本人，三格，生效的一格高亮。
- **分组 → 节点**：条件（地区 / 标签 / 节点，且 / 或）→ 匹配到的节点 → 成员实际看到的节点。

## 4. 用户端与登录

### 现状

`MeView.tsx`（1661 行）手机上自上而下：公告与服务状态横幅 → 头像行与三点菜单 → 四个标签 → 推荐客户端大卡 → 订阅链接卡 → 用量卡 → 快捷链接 → 紧急访问。登录页最多同时出现七项：密码表单、验证码、忘记密码、注册、通行密钥、SAML、OIDC。

### 问题

- **首屏不是用户要的东西。** 订阅链接和用量要往下滚；二维码默认模糊，要先点一下（:999，已核对）。
- **到期进度条按固定 30 天计算（:1548，已核对）。** 年付套餐在最后 30 天之前一直是满格，条的含义不对。这是显示逻辑的错误，不只是样式。
- **停服说了原因，没说怎么办。** 横幅（:599–635）没有按钮；紧急访问卡在页面最底（:1256）。停服时订阅链接照常显示，用户会以为是客户端坏了。
- **订阅卡讲不清楚。** 二维码、打码链接、眼睛、复制同时出现；说明文字让人以为复制前要先显示（:1045）。推荐客户端和订阅链接是两张互不相干的卡。
- **"重置凭证"和"复制"在同一行**（:1065），它会让旧链接失效。
- **安全功能藏在没有文字的三点菜单里**（:880），而且都是术语（TOTP、Passkey）。
- **登录页的按钮带协议名**（"使用 SAML 登录"）。

### 新结构（手机为先）

1. 状态条，只在异常时出现：一句原因 + 一个按钮（"查看临时延长" / "联系管理员"）。
2. "我的订阅"卡作为首屏主角：用量与到期一行、主按钮"复制订阅链接"、三步引导。
3. 折叠区：其他客户端、扫码导入、重置订阅链接（带二次确认）。
4. 流量趋势、服务器状态在下一屏。
5. 独立的"账号安全"页：改密码、验证码应用、通行密钥、应急登录码，每项一句人话说明。

### 图示

- 三步引导：复制链接 → 打开客户端 → 导入。
- 用量条和到期条：写出"还剩多少""还有几天"，到期条按套餐实际时长算。
- 停服状态图：说明这是服务暂停，账号仍可登录。

## 5. 访问控制（`views/admin/accessControl/`，48 个文件）

本节的判定顺序是对照 `docs/access-control.md` 得出的，没有对过后端实现，标为**推断**。

### 现状

四个标签：策略、列表、白名单分组、记录（`AccessControlView.tsx:214–217`）。另有五个页面级抽屉和一个设置对话框。功能入口还散落在节点页（来源规则，`NodesView.tsx:4118`，已核对只挂在那里）、面板页、分组编辑和法律文档页。

### 问题

- **做最常见的事（拦截某类站点）要先懂六个概念**：策略、列表、仅报告、范围、下发、节点覆盖。
- **标签顺序和工作顺序相反。** 策略要引用列表，所以得先建列表，但策略排第一。
- **一条策略的"定义、应用、观察"分散在五处**：编辑弹窗、弹窗底部的范围、节点覆盖抽屉、记录标签、节点页的来源规则。
- **"一条连接会怎样"只能单次模拟**，没有一张完整的判定流程图。
- **"仅报告"同时是三样东西**：策略状态、判定轨道上的一步、白名单分组的状态。
- **"放行"有三种**：放行策略、白名单、豁免账号；记录页还有"添加例外"。
- **页头的"查看账号…"打开的是风险中心的抽屉**（`AccountDrawerHost.tsx:9`）。

### 新结构

按工作顺序排标签：

1. 概览：全局状态 + 判定流程图 + 下一步建议；"测试目的地"做成常驻面板。
2. 规则：策略与列表合并，编辑策略时可以就地新建列表。
3. 适用对象：分组白名单、豁免账号、来源规则（至少在这里有入口）。
4. 节点：执行状态、记录模式、主机名解析。
5. 记录。

首次使用的引导：选模板 → 试运行看命中 → 开启 → 确认节点已执行。策略和分组白名单各有详情页。

### 图示

- **判定流程图**：连接 → 来源规则 → 放行策略 → 豁免账号 → 拦截策略 → 分组白名单 → 试运行 → 未命中则放行。顺序要先对过后端再画。
- **应用范围图**：策略 → 范围 → 展开成节点，每台节点标"是否真的在执行"。数据已有（`NodePolicyStatusRow`）。

## 6. 风险中心、诊断与监控类页面

这两块是近期重做过的，有不少值得保留和推广的做法。

### 值得保留并推广的

- **状态全在 URL 里**（`RiskCenterView.tsx:36–64`）：标签、筛选、抽屉里的账号都可回退、可分享。这正是迁移计划 3.1 要的，应抽成通用 hook。
- **指标卡同时是筛选**，再点一次取消（`QueueMetricCards.tsx`）。
- **行菜单和抽屉共用同一张操作表**（`QueueTab.tsx:389`）。
- **概览固定六行**，没结论的显示"尚未计算"，不会消失（`OverviewTab.tsx:198–202`）。
- **策略卡的格式**：开关 + 预设（宽松 / 标准 / 严格 / 自定义）+ 关键阈值 + 高级折叠。
- **诊断页的问题条目格式**：是什么、影响、怎么办、去哪里（`FindingList.tsx`）。可作为全站"问题条目"的模板。

### 问题

- **"现在要我处理什么"没有统一入口。** 通知铃把五类提醒指向五个页面（`NotificationBell.tsx:33–43`，已核对）。概览页、节点问题、同步任务、诊断各有自己的问题列表。同一个故障可能在几处同时出现（哪些会重复属推断）。
- **证据要读三层**：队列行摘要 → 抽屉概览 → 时间线里的记录详情。
- **策略效果难预测。** 信任账号只免除六项检测中的三项；设备数卡的一个参数与另一张卡共用，改一张会动另一张。没有"按这个设置会影响多少账号"的预览（推断）。
- **"在线"标签和抽屉的"连接"是同一份数据的两个视角**，"设备"是第三个相近视角。
- **队列有四套筛选互相清除**（`QueueTab.tsx:36–57`）。
- **诊断页对日常运维太技术化**：计数器、直方图、p95 和需要处理的问题混在一起。

### 新结构

- 新增**"需要处理"收件箱**，放在概览页首屏，并作为通知铃的落点。每条 = 严重程度 + 一句话 + 影响对象 + 一个主要动作；同一对象的问题合并成一条。
- 风险中心只回答"哪个账号可疑、怎么处理"；"在线"并入队列的一个视图。
- 节点问题并入节点详情页的"问题"标签；同步任务保留为明细页。
- 诊断默认只显示结论和问题列表，区域卡与原始指标折叠。

收件箱是新功能，不是换皮，需要单独决定做不做（见迁移计划第 8 节）。

### 7.2 文案规则

依据 Ant Design 文案规范（蚂蚁集团），逐条适用于所有迁移后的页面：

1. **称呼用"你"，不用"您"**；同一句里不混用"你"和"我"。
2. **用词统一**：同一事物只用一个词；操作名称与它打开的页面标题一致。
3. **用行业通用词**：专业术语要准确，采用所属行业认可的说法（见 7.1）。
4. **固定写法**：用"登录"不用"登陆"；用"其他"不用"其它"；指代当前事物用"此"不用"该"。
5. **报错写法**：用"无法完成"代替"失败"；不责怪用户；必须告诉用户下一步怎么做。"抱歉"只用于系统造成的结果。
6. **少用命令口气**：避免"不能""不要""请勿"；避免"绝不"之类的绝对说法。
7. **重要信息放最前**，不埋在段落里；隐私信息可以"点击后可见"。
8. **空格**：全角与半角字符之间加空格，如"2 个""50%"；链接与文字之间加空格。
9. **标点**：按钮、标题、标签、输入框提示、表格里的句子不加句号；多句文案要加。连接号用半角（2026-11-18）。感叹号只在问候、祝贺时使用。
10. **数字用阿拉伯数字**。
11. **英文大小写**：产品名全称首字母大写，缩写全大写（SSO、CDN、TOTP）；不整词大写。

这些规则与迁移计划 3.4 的"成功提示不带'成功'二字和感叹号""确认按钮写动词"一致，以本节为准。

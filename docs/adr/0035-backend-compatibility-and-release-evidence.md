# ADR 0035：后端兼容承诺与发布证据

- 状态：提案；规范基线已整理，实施门禁待完成
- 日期：2026-09-18

## 背景

PSP、PN 和第三方面板独立发布。协议能解析、某功能可用、代理能连接、程序可升级和数据可
回退是不同结论。当前旧 PN 协议矩阵、第三方实测范围及升级机制测试已有基础，但不能共同
推出未经验证的双向兼容或历史升级承诺。

## 决策提案

采用 [后端兼容、升级与 CI 规范](../compat-policy.md) 作为实施基线：

1. 独立管理程序、wire、能力、状态 schema 和升级 contract；新增限制语义必须能力门控。
2. 兼容声明绑定具体组合与功能 profile，采用有界双向验证，新反方向承诺以完整测试为前提；保留 ADR 0033 的既有旧 PN 支持。
3. 支持政策与 CI 证据分开，逻辑政策统一驱动测试选择、运行判断及发布资格。
4. 升级判断所有中间组合，每条升级和回退边独立验收；同源码修改版本号不证明历史迁移。
5. 发布门核对预期测试集合与实际结果，绑定最终源码／发布物身份，意外跳过不得通过。

本文不改变现有 API 枚举、不扩大兼容 JSON 范围，也不表示所有 CI 已实现。实施顺序和
逐项验收见规范第 9 节；完成后再更新本 ADR 状态及实施证据。

## 后果

需要维护可复现的历史实现、第三方隔离环境和持久报告；发布验证成本增加，但兼容声明可追溯。
两仓无需锁步发版；桥接版本与受限基础模式允许逐步升级。维护窗口是独立政策选择，不能在
优化 CI 时顺便移除支持版本。

## 考虑过但未采用的方案

- 只比较版本范围：不能证明可选能力、已知坏版本、真实链路或数据回退。
- 要求双方永远同步升级：没有解决中间状态，扩大故障影响范围。
- 只测最新源码：不能证明旧实现及历史数据行为。
- 只保留人工实测说明：有价值，但不能成为持续阻止回归的发布门。
- 立即引入外部契约管理服务：当前仓库 JSON 与 CI 可表达所需证据，先避免额外基础设施。

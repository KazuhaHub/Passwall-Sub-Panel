# ADR 0030：QUIC 与普通 UDP 独立、无地区假设地控制

- 状态：已接受
- 日期：2026-09-11

## 背景

把所有 `UDP/443` 固定拒绝可以迫使浏览器从 HTTP/3 回退到 TCP，但会剥夺用户对良好 UDP
线路的选择。把中国地址直连、其他地址拒绝同样不成立：海外用户和回国代理的方向与默认
中国出境配置不同。

Mihomo 有 `PASS`，sing-box 没有对等的 selector outbound。把 `PASS` 翻译成 `direct` 会造成
平台间的静默直连泄漏。

## 决策

1. 在私网/LAN 直连规则之后，先用 `NETWORK=UDP + DST-PORT=443` 进入 `⚡ QUIC控制`。
2. 随后才用 `NETWORK=UDP` 进入 `🎮 UDP控制`。TCP 不受影响。
3. `⚡ QUIC控制` 默认成员是 `🎮 UDP控制`，然后是 `🚀 节点选择` / `DIRECT` / `REJECT`。
   这既保留一个 UDP 总开关，也允许订阅用户单独覆盖 QUIC。
4. 两个输出都生成真实的 selector。sing-box 翻译器会把 Mihomo `AND` 条件合并成一条
   `{network: udp, port: 443}` 路由，而不使用隐藏的强制拒绝规则。
5. sing-box 输出遇到 `PASS` 时忽略该规则/成员以继续匹配，绝不翻译成 `direct`。
6. 删除 Mihomo 不支持的 `REJECT-DROP-BIT`，只保留 `REJECT` 和 `REJECT-DROP`。

## 后果

- 不再对用户所在地或代理方向做假设。
- 拒绝 QUIC 只会影响用户选择的 UDP/443；浏览器可回退 TCP。
- 这是对 HTTP/3 常见端口的精确匹配，不是协议深度识别。使用非 443 端口的 QUIC 归普通 UDP
  策略处理。
- 启动 seeder 会将“两个文件都与旧官方默认逐字节一致”的模板+规则集作为一个版本包自动升级；
  任一文件有管理员修改就两个都不动，由管理员手动合并或“恢复默认”。

## 未采用的方案

- **固定拒绝 UDP/443**：简单，但浪费可用的 QUIC 线路且无法由用户恢复。
- **中国直连、其他拒绝**：地区假设错误，且规则优先级会覆盖用户意图。
- **所有 UDP 共用一个组**：无法“只禁 QUIC，保留游戏/语音 UDP”。
- **sing-box 将 `PASS` 映射为 `direct`**：语义不等价，可导致静默绕过代理。

# ADR 0039：节点级 VLESS 路由线路与“按线路选择”引用

状态：已接受，已实现并完成有界本地验收（2026-10-16），待人工体验反馈。

## 背景

管理员希望将同一 VLESS 入站以多个独立代理条目发布，并使不同条目选用不同的既有出站。此前的服务端出站/路由管理大页面方案已废弃，不属于当前实现基线。旧“按节点选择”成员通过 NodeID 动态展开中转，不能改成只选择直连线路，也不应强制迁移成某一时刻的线路快照。

## 决策

- 节点编辑原中转区域提供“中转线路 / VLESS 路由线路”两个标签页，分别保存数据，不自动交叉展开；沿用一个保存按钮，同步结果不确定时不假装保存全部成功。两页使用一致的控件格式与布局，新增按钮位于标题右侧；路由线路首排为可选名称、启用、上移、下移、删除，下面依次选择线路入口和出站；空名称回退到出站标签。不显示成功状态横幅和 route 数值标签，异常提示继续保留。
- PSP 只读取 3X-UI 已有出站元数据，不创建、修改或删除出站。功能仅用于 3X-UI 的 VLESS 节点，不以面板或内核的具体版本号限制使用。
- 保留 `kind: node` 的动态集合含义，并包含该节点新增的 VLESS 路由线路。增加 `kind: line`，通过父 NodeID 与稳定线路 ID 精确选择直连线路、中转线路或 VLESS 路由线路。历史中转只补充 ID，不重解释旧代理组数据。
- 每条 VLESS 路由线路使用 `inboundTag + vlessRoute` 匹配该入站所有用户，指向已有出站标签；PSP 只维护登记的规则，将其放在用户规则之后。既有规则首次命中优先，前置兜底可以遮蔽新规则。
- 派生订阅仅修改实际已应用 UUID 的第 7、8 字节，不创建真实 inbound/client，不代替用户授权。每条路由默认依赖直连，也可按稳定中转 ID 选择一个入口；不自动交叉展开。直连隐藏或选中中转停用/删除时，依赖线路的实际可用状态同步关闭，订阅、规则预览与用户状态页均不发布；保留配置启用意图，入口恢复后可重新生效。
- 整模板更新使用后端租约、状态 CAS、写前变化检查和写后回读。上游无 CAS，外部管理员仍须遵守应用窗口单写模板。只读漂移检查只能撤下本地线路，不能自动重写用户模板。
- 停用/删除线路移除其规则并停止发布，不撤销已下载凭据、不保留阻断规则；同一节点内退役 ID/route 值不复用。
- 中转状态按启用线路自动探测和展示，不再提供独立开关。用户状态页加入可发布的 VLESS 路由线路，沿用订阅的已应用凭据/后端绑定保护，复用所选入口的状态与检查时间，不宣称已验证出站可用；两类线路均遵循各自“仅显示线路名称”选项，名称未填的中转仍使用本地化序号，避免在状态接口暴露入口地址。

## 后果

“按节点选择”中的新线路自动进入既有代理组是明确接受的行为，而不是数据格式兼容问题。需要精确控制时使用“按线路选择”。删除、排序、重命名不能改变线路身份。已删除引用保留失效提示，不自动指向另一条线路。

凭据确认、节点元数据与规则变化均会改变派生订阅的可发布集合，必须在确认落盘后失效对应缓存；不能用延长等待或缩短缓存 TTL 掩盖漏掉的失效链路。后端/端口/协议绑定变化后，历史确认不能直接沿用。

所有管理员页面遵循 `docs/admin-edit-state.md`：以写响应更新本地条目、保护未保存草稿、明确部分成功；私密出站配置不得进入候选 DTO 或审计回显。

## 考虑过但未采用

- 独立服务端网络管理页和草稿/预览/应用流程：超出当前节点级线路需求，且已被用户否决。
- 将旧 NodeID 引用改成“仅直连线路”或自动展开为固定列表：分别会删掉旧中转，或丢失未来自动加入的集合语义。
- 将 route 字段混入中转并自动交叉展开：混淆入口与出站选择，造成不必要的条目膨胀。
- 将 PSP 路由插到最前：会抢过用户自定义规则的优先级。

详细操作、验证进度与已知边界见 [VLESS 路由线路（V2）](../vlessroute-v2.md)。

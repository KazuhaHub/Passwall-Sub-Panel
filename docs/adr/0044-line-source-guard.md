# ADR 0044：按来源校验线路身份（堵住按线路倍率的绕过）

- 状态：已接受并已实现（2026-11-18，所有者批准）；实现于 4.3 beta.5，之后按倍率类重做（PSP 一侧；Node 一侧见其 README「Source guard」）
- 关联：[ADR 0043](0043-per-line-client-identity.md)、[流量倍率](../traffic-multiplier.md)、
  [托管中转](../transit-lines.md)

## 背景

ADR 0043 给每条线路一个客户端身份，按身份所在的行记账。但直连、直接转发（托管或外部）与 CDN
线路都终止在落地节点的同一个监听器上，这个监听器接受这些线路的全部身份，看不出连接实际走的是
哪条路：

- 用户把直连 UUID 填进较贵中转的入口，按直连倍率计费；
- 中转较便宜时，用户拿中转身份直连落地，按中转倍率计费。

加密隧道线路有自己的监听器，不受影响。

Xray 只按用户累计流量，不记录每条连接的来源，无法事后按来源拆分计费。所以改为在落地拒绝
"身份与来源不符"的连接：每个字节只能经过它身份对应的线路，按行记账即按路径记账。

## 决策

### 1. 倍率类与线路来源

同一个落地监听器上，终止在它上面的线路（直连、托管或外部直接转发、CDN；加密隧道线路有自己的监听器，不算）
按有效倍率分组（缺省 1000 千分位）：

- 含直连倍率的一类是**直连类**。其中的中转线路与直连同价，用谁的身份都一样，**不需要任何来源**。
- 其余每一类是**计价类**，来源组 = 该类各线路有效来源的并集。

一条线路的来源：

- **托管直接转发**（`EntryPanelID ≠ 0`，`Mode = ""`）：入口服务器的地址。由入口 Node 在完整回报中上报的本机全局
  单播地址，加上 PSP 看到的该服务器同步来源地址，再加管理员在线路上补充的 CIDR。
- **CDN**（`Mode = cdn`）：默认用 Cloudflare 公开的 IP 段。PSP 每天从 Cloudflare 自动拉取，校验后保存最后一次
  成功结果，拉取失败时沿用上次结果，从未成功时用内置快照；管理员关闭自动拉取后一律用内置快照。线路上填了自己的
  CIDR 时只用线路的。
- **外部中转**（`EntryPanelID = 0`，`Mode = ""`）：管理员填写的出口地址。

管理员填写的 CIDR 在所有保存路径（元数据、线路、创建向导、导入）统一规范化：拒绝主机位、IPv4 映射、过宽的前缀
（IPv4 短于 /8，IPv6 短于 /19）。

### 2. 执行（Passwall Node 落地）

来源组（`SourceSet`）的键按（监听器，倍率）确定：`src_<节点>_f<倍率千分位>`。PSP 在配置里下发各计价类的来源组，
在名册里给每个客户端标注约束：

- 计价类的客户端：`allow_from` = 本类的键，**总是**带，即使来源未知或这一类被撤下（此时引用这个键但不下发来源组，
  Node 因而拒绝该客户端的全部连接，失败即关闭）。计价类的客户端不会没有约束。
- 直连类的客户端（直连线路与同倍率的中转线路，包括没有来源的外部线路）：`deny_from` = 该监听器上已知且非空的各计价类
  的键；挂在多个监听器上的旧行取各监听器的并集，超过 64 个时禁用该客户端而不是少写。

Node 把它们编译成路由规则，放在策略规则之前。来源指核心看到的连接来源；经过 SNI 共用端口时是共用端口收到的来源
（PROXY protocol 传入）。组缺失时：`allow_from` 引用的组不存在则拒绝该客户端的所有连接；`deny_from` 引用的组不存在则
忽略。只发给声明 `transit.source_guard.v1` 的 Node。

### 3. 被拦截的来源

Node 记录被来源规则拒绝的连接（Xray 通过规则 webhook，sing-box 不上报），在完整回报中上报
`(来源组, 来源地址, 次数, 最后时间)`，每次最多 256 条。命中名的是类的来源组，PSP 按（监听器，倍率）映射回类和线路：

- 来源地址不在任何一类的来源里：**未登记来源**，属于这一类某条线路但来源里没写，可一键加入这一类中有自己地址的线路
  （只改那条线路的来源）。CDN 线路用 Cloudflare 默认时不提供（加一个地址会替换整个默认）。
- 来源地址已在命中的来源组（或另一类的来源）里：**身份用在了错误的线路上**（直连类身份经计价路径，或计价身份来自另一类的
  地址），加入线路无济于事，不提供加入。

### 4. 不能执行的落地

落地是 3X-UI / S-UI、Node 未声明能力，或监听器的来源不是连接本身的地址时，无法按来源拒绝。**可执行的监听器**要求核心不会
从客户端可控的头里取来源：

- sing-box：任何传输（ws、httpupgrade、http/h2、grpc）都不可执行，只有纯 TCP（含 TLS/REALITY）可以；
- Xray：`sockopt.trustedXForwardedFor` 非空，或流设置、入站设置里任意位置设了 `acceptProxyProtocol`，不可执行
  （Passwall 前端加的 PROXY 头不算，前端拒绝自己设了它的监听器）。

不可执行时，同一监听器上的直连与直接转发、外部中转、CDN 线路必须使用相同倍率，保存时拒绝不同的倍率，错误里说明
监听器的传输让客户端能自己决定来源地址。CDN 线路通常落在 ws/grpc/httpupgrade 上，所以在 sing-box 落地上不能与直连
定不同的价。已保存的不同倍率在能力消失后不再发布，并记为线路问题。

能执行时保存规则（所有保存路径，导入也一样）：

- 两类的已知来源不得重叠（任一类的某个前缀与另一类的某个前缀相交，含 CDN 的 Cloudflare 默认与直连类中转线路的来源），
  否则无法区分：**来自相同地址的线路必须使用相同倍率**，例如两条倍率不同的 CDN 线路都用 Cloudflare 默认会被拒绝。
- 计价类最多 64 个（直连类客户端的 `deny_from` 装得下），一类来源的并集最多 1024 条（一个来源组的上限）；不截断、
  不跳过。
- 倍率与直连不同的外部中转线路必须填写来源地址；托管直接转发在入口地址尚未知道前不发布。

已保存的状态后来变得不合规（能力消失、Cloudflare 或入口地址变化造成重叠或超限）时，PSP 不下发有问题的方案：受影响的
计价类线路不再发布并记为节点问题，它们的客户端继续带 `allow_from`（来源组不下发）保持失败即关闭。

### 5. 渲染与应用

撤销 ADR 0043 §5 的回退：直接转发、外部中转与 CDN 线路在自己的身份应用之前不发布，不再借用直连身份。计价类线路的
身份只有在已应用的名册带着预期的约束、且已应用的配置带着它的来源组之后才记为已应用，所以订阅不会在约束生效前就
发出这条线路。

## 后果

- 每个字节都按它实际经过的线路类计费，"设在哪就按哪算"在直接转发与 CDN 上也成立；同价的线路互不限制。
- 给已有的转发或 CDN 线路设上与直连不同的倍率后，客户端手里用直连身份经这条线路的旧配置会失效（直连身份拒绝来自计价类
  来源的连接），直到用户刷新订阅拿到该线路自己的身份。
- 入口服务器若用未上报的地址出站，该类会被误拒。第 3 条的上报与告警用来发现它。
- 用户本人的地址落在某个计价类的来源内（例如在入口服务器上测试）时，直连身份会被拒绝。
- 来自相同地址的线路只能同价；想给同一批地址定两个价是做不到的，保存时就会被拒绝。
- 名册与配置变大：每个客户端多一个来源约束，配置多出各类来源组。CDN 组约二十条 CIDR。
- PSP 每天向 Cloudflare 发两次匿名 GET，不带任何部署信息。

## 考虑过但未采用的方案

- **按来源拆分计费**：Xray 没有按连接的流量与来源，只有 sing-box 有，做不到一致。
- **只要求同一监听器同倍率**：最简单，但直接转发与 CDN 线路就不能单独定价，不符合所有者要求。
- **中转线路用单独的隐藏监听器**：仍需按来源限制该监听器，且 3X-UI 落地要改面板模板（4.3 刚移除
  这类写入）。

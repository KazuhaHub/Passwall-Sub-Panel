# ADR 0044：按来源校验线路身份（堵住按线路倍率的绕过）

- 状态：已接受并已实现（2026-11-18，所有者批准）；实现于 4.3 beta.5（PSP 一侧；Node 一侧见其 README「Source guard」）
- 关联：[ADR 0043](0043-per-line-client-identity.md)、[流量倍率](../traffic-multiplier.md)、
  [托管中转](../transit-lines.md)

## 背景

ADR 0043 给每条线路一个客户端身份，按身份所在的行记账。但直连、直接转发（托管或外部）与 CDN
线路都终止在落地节点的同一个监听器上，这个监听器接受这些线路的全部身份，看不出连接实际走的是
哪条路：

- 用户把直连 UUID 填进较贵中转的入口，按直连倍率计费；
- 中转较便宜时，用户拿中转身份直连落地，按中转倍率计费。

加密隧道线路有自己的监听器，不受影响。

Xray 只按用户累计流量，不记录每条连接的来源，无法事后按来源拆分计费。所以改为在落地拒绝
"身份与来源不符"的连接：每个字节只能经过它身份对应的线路，按行记账即按路径记账。

## 决策

### 1. 线路来源

每条终止在落地监听器上的中转线路（直接转发、外部中转、CDN）有一组来源地址（CIDR）：

- **托管直接转发**（`EntryPanelID ≠ 0`，`Mode = ""`）：入口服务器的地址。由入口 Node 在完整回报中
  上报的本机全局单播地址，加上 PSP 看到的该服务器同步来源地址，再加管理员在线路上补充的 CIDR。
- **CDN**（`Mode = cdn`）：默认用 Cloudflare 公开的 IP 段。PSP 每天从 Cloudflare 自动拉取
  （`https://www.cloudflare.com/ips-v4`、`/ips-v6`），校验后保存最后一次成功结果，拉取失败时沿用
  上次结果，从未成功时用内置快照。管理员可关闭自动拉取。线路上填了自己的 CIDR 时只用线路的
  （其他 CDN）。
- **外部中转**（`EntryPanelID = 0`，`Mode = ""`）：管理员填写的出口地址。

直连线路没有来源组：除各中转线路来源之外的地址都算直连。

### 2. 执行（Passwall Node 落地）

PSP 在配置里下发来源组（`SourceSet`：键与 CIDR），在名册里给每个客户端标注来源约束：

- 中转线路的客户端：`allow_from` 该线路的来源组。来源不在组内的连接被拒绝。
- 直连客户端：`deny_from` 同一监听器上各中转线路的来源组。来源在任一组内的连接被拒绝。

Node 把它们编译成路由规则，放在策略规则之前：Xray 用 `user` + `source`（"不在组内"由 Node 计算
补集）指向 block，sing-box 用 `auth_user` + `source_ip_cidr`（`invert`）。来源指核心看到的连接来源；
经过 SNI 共用端口时是共用端口收到的来源（PROXY protocol 传入）。

组缺失时：`allow_from` 引用的组不存在则拒绝该客户端的所有连接（失败即关闭）；`deny_from` 引用的
组不存在则忽略。

只发给声明 `transit.source_guard.v1` 的 Node。

### 3. 被拦截的来源

Node 记录被来源规则拒绝的连接（Xray 通过规则 webhook，sing-box 尽力而为），在完整回报中上报
`(来源组, 来源地址, 次数, 最后时间)`，每次最多 256 条。PSP 把它显示为线路问题，例如"线路 X 收到来自
未登记地址 a.b.c.d 的连接，已拒绝"。管理员可把该地址补充到线路来源。

### 4. 不能执行的落地

落地是 3X-UI / S-UI，或 Node 未声明能力时，无法按来源拒绝。此时同一监听器上的直连与直接转发、
外部中转、CDN 线路必须使用相同倍率，保存时拒绝不同的倍率。已保存的不同倍率在能力消失后
（例如 Node 降级）不再发布倍率不同的中转线路，并记为线路问题。

能执行时，倍率与直连不同的外部中转线路必须填写来源地址，否则拒绝保存；托管直接转发在入口地址
尚未知道前不发布。

### 5. 渲染

撤销 ADR 0043 §5 的回退：直接转发、外部中转与 CDN 线路在自己的身份应用之前不发布，不再借用
直连身份（直连身份经过中转来源会被拒绝）。

## 后果

- 每个字节都按它实际经过的线路计费，"设在哪就按哪算"在直接转发与 CDN 上也成立。
- 入口服务器若用未上报的地址出站，该线路会被误拒。第 3 条的上报与告警用来发现它。
- 用户本人的地址落在某条中转线路的来源内（例如在入口服务器上测试）时，直连身份会被拒绝。
- 名册与配置变大：每个客户端多一个来源约束，配置多出来源组。CDN 组约二十条 CIDR。
- PSP 每天向 Cloudflare 发两次匿名 GET，不带任何部署信息。

## 考虑过但未采用的方案

- **按来源拆分计费**：Xray 没有按连接的流量与来源，只有 sing-box 有，做不到一致。
- **只要求同一监听器同倍率**：最简单，但直接转发与 CDN 线路就不能单独定价，不符合所有者要求。
- **中转线路用单独的隐藏监听器**：仍需按来源限制该监听器，且 3X-UI 落地要改面板模板（4.3 刚移除
  这类写入）。

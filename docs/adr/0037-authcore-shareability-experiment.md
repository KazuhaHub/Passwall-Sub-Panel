# ADR 0037：authcore 共享收益实验的测量口径与退出判据

- **状态**：已接受（2026-09-18）。**判据在结果出现之前冻结。** 修改门槛必须重新立项并在实施记录里保留原结论，不得在看到行数后回调。
- **日期**：2026-09-18
- **相关代码**：无（本 ADR 不改变产品行为）。测量与职责表落在 `docs/authcore-migration-measurement.md`。
- **前置**：`docs/authcore-migration-plan.md`（§1、§2.4、§9）、ADR 0036、[authcore 的共享收益评估](https://github.com/KazuhaHub/authcore/blob/1d5b0ee6a6799cfe57c5d5ec57037bcefd0fc5f8/docs/does-authcore-earn-its-place.md)、[authcore ADR 3](https://github.com/KazuhaHub/authcore/blob/1d5b0ee6a6799cfe57c5d5ec57037bcefd0fc5f8/docs/adr/0003-ratelimit-and-clientip.md)

## 背景

### 这件事的性质

`authcore` 自己的评估（2026-09-18）得出结论：四个包中只有一个消费者（Report Portal），按 ADR 3 的退出标准**每个包都不成立**；它同时指出 PSP 从未被给过选择，且 PSP 在四个概念上都已有更小的本地实现（`saml` 711 / `passkey` 537 / `captcha` 212 / `geoip` 156，对 authcore 的 1117 / 888 / 753 / 448）。该评估把 PSP 列为"有信息价值的第二消费者实验"（§8.1）。

ADR 3 的退出标准把 `clientip` 提取在同一天撤回——理由是第二个消费者无法在不放弃既有部署模式的前提下采用它。这是本仓库已经用过两次的先例（`audit`、`clientip`）：**判据是"真实消费者是否可测量地受益"，不是"代码好不好"。**

因此本实验的失败是**合法结论**，不是需要避免的结果。**补足第二个消费者本身不是验收目标。**

### 风险：一条会让实验失效的路径

如果不预先冻结测量口径，"接入 authcore"会退化成"证明接入成功"：行数口径可以在拿到数字后调整，职责转移可以靠移动文件或加一层包装声称完成，加固收益可以被记成共享收益。三种都发生过或几乎发生。本 ADR 的全部内容就是堵这三条路。

### 加固收益与共享收益必须分账

ADR 0036 的加固（Destination 必填、多断言拒绝、弱签名拒绝、请求绑定、fail-closed、配置快照）**不依赖 authcore**，会先独立交付。M 线不得把这些记成自己的新增收益，也不得声称"因为加固所以共享成立"。同理，账户/角色/克隆拒绝等策略本来就留在 PSP，不冒充转移。

## 决策

### 1. 每包记录三个提交

对每个参与实验的包记录：**B0**（原实现）、**H**（已交付加固、仍用本地引擎的对照）、**M**（替换候选）。

- **共享成本与收益比较 H→M。** `B0→H` 的安全收益与成本单列，不计入共享账。
- H 取"以 M 实际分支基点中仍用本地引擎的版本"；若加固发布后主干已有其他改动，以该版本为 H，另保留最初加固发布 SHA。期间无关变化不得计入该包实验。
- GeoIP 没有前置加固时 H 可等于 B0。

### 2. 测量范围

计数范围（不得只计 `internal/adapters/authcore`）：旧实现、替换适配器、ports DTO、service/handler/app 装配改动、配置快照、存储桥接，以及为支持该包而在 authcore 新增的 API。

| 符号 | 定义 |
| --- | --- |
| `A` | H→M 在 PSP **增加**的生产 Go 行 |
| `D_pre` | 删除的 **B0 原有**实现（不含 H 阶段新增） |
| `D_hardening` | 删除的 **H 新增、独立成立**的加固实现（ADR 0036 落地的那些） |
| `D_bridge` | 删除的**纯为接库搭建、随后移除**的桥接代码 |
| `Δ_actual` | `A − D_pre − D_hardening`（相同安全能力下 PSP 的实际净变化） |
| `Δ_conservative` | `A − D_pre`（不给新增加固的删除额记收益） |

口径要求：

- 使用固定物理行口径，含行内与整行注释；测试与文档单列，**不混进生产净值**。
- 保存 `git diff --numstat --find-renames H M` 与逐文件归属表。
- **纯移动不算减少职责**；禁止改格式、压行、移动注释或删测试来美化测量。
- 共享装配文件按变更块**只分配一次**，不能多包重复认领同一段删除量。
- H 已有的配置快照、请求表与保护逻辑**原样保留**的成本不再记作 M 新增；若替换造成额外桥接或重复实现，那部分**必须**计入 M。
- `D_bridge` **不产生任何收益**，不得进入 `Δ_actual` 的正向项。

### 3. 三个口径的归类必须从职责表推导，不在事后逐行判断

`D_pre` / `D_hardening` / `D_bridge` 的归属**直接从职责清单推导**，不在拿到行数后逐行归类——否则同一段代码会在结论不利时被重新归类，这正是本 ADR 要防的事后移动门槛。

职责清单要求：每个协议判断/通用机制给一个**固定 ID**，写明 **H 的实现位置、对应的测试、以及 M 的责任方**。

只有同时满足以下三条才算**一项真正转移**：

1. PSP 已删除该判断的实现；
2. authcore 有**正式契约**（接口/文档承诺，或可分类的错误语义）；
3. authcore 有**回归测试**保护该契约。

**包装库调用、移动文件、减少 import 都不算。** 并区分"安全判断转移"与"普通机制转移"——后者不能替代前者去满足预算例外的条件。

### 4. 判据（冻结）

| 判据 | 决定 |
| --- | --- |
| 任一安全/兼容验收失败，或依赖 authcore **未声明**且**无上游测试**的行为 | **不得合并替换**；先修契约，修不了则 rejected/deferred |
| `D_pre = 0`，或没有任何一项实际转移 | **rejected**：只有多一层包装不足以支持采用 |
| `Δ_conservative <= 0` 且至少转移一项职责 | **可以采用**；报告实际减少了什么 |
| `0 < Δ_conservative <= 25% × D_pre` 且至少转移一项**有上游回归保护的安全判断** | SAML/Passkey 可以采用：显式接受有限维护成本，换取集中安全维护 |
| `Δ_conservative > 25% × D_pre`，或 `Δ_conservative > 0` 但 PSP 自维护安全判断没有减少 | **rejected**；必须记录失败并保留 H，不用"已经花了时间"解释继续迁移 |
| GeoIP / 重新准入的验证码 | 要求 `Δ_conservative <= 0` 且有真实机制转移；**不适用**上述预算例外 |

**预算分母是 `D_pre`，判定变量是 `Δ_conservative`——两者必须同时生效。** 只把分母改成 `D_pre` 而仍用 `Δ_actual` 判定是无效的：`Δ_actual` 会把 H 阶段新增加固的删除额记为收益，使 `Δ_conservative <= 0` 那条在有脚手架删除量时照样通过。

用户体验、安全强度与正确性是**硬门槛**，不能用行数收益抵偿。历史的 711 行**不设为永恒阈值**——它只是当时的测量，`D_pre` 按实际测量得出。

### 5. 每包独立结论

- 结论取值：**adopted / rejected / deferred / not_attempted**。后两者**不算实验已经证明有效或无效**。
- SAML 是首个必须给出实测结论的候选；**Passkey 独立候选，不与 SAML 捆绑通过**。SAML 被拒绝不自动否定 Passkey，也不自动授权扩大抽象修补范围。
- 通过共享验收的包**只保留一套生产实现**；实验失败的包**保留加固后的本地实现及其测试**，不因此撤销加固。
- 删除仅服务于失败候选的 PSP 适配层。authcore 已发布 API 如何维护，由该库按其他消费者实际需求另作决定，**不在 PSP 任务里删除整个共享仓库**。
- 结论只证明**这个包对 PSP**的适用性。即使 SAML 成为第二个消费者，也不能据此替 Passkey、验证码或整个 authcore 自动宣布成功。

### 6. 依赖成本分列记录

按 `docs/authcore-migration-plan.md` §2.4：对构建制品记录 `go version -m <制品>`，并记录 `go list -m -json all`、`go mod graph`，用 `go mod why -m <模块>` 解释四个上游依赖的保留原因。

**不得宣称"消除了上游库依赖"**：authcore 的公开 API 本身就暴露 `*crewjam/saml.EntityDescriptor` 与 `webauthn.Credential`，SAML/Passkey 适配器仍需直接导入上游库。允许 `direct → indirect`，但**不把它计作依赖风险消失**。authcore 新增依赖与版本升级必须在对应 PR 的审计中逐项说明。

## 后果

- **保守门槛会否决一些实际有益的迁移。** `Δ_conservative` 不给"把新增加固交给共享库"记收益，而这件事本身是真实收益。接受这个代价的理由是：判据必须在看到结果前就固定，任何"这次算例外"的口子都会让门槛失效。
- **`Δ_actual` 仍然记录。** 它的作用是让日后可以带着完整信息重审一次被否决的候选，而不是在评审现场放宽门槛。
- **rejected 是有成本的结论。** 它意味着已经写好的适配层被删除、加固保留。这是预先接受的成本，不是失败。
- **判据本身不可在实验中途调整。** 需要调整即重新立项，原结论保留。
- **不变量**：加固收益与共享收益分账；`D_bridge` 无收益；每包结论独立；失败不撤销加固。

## 考虑过但未采用的方案

1. **只用一个 `Δ` 判定。** 未采用：无法区分"减少原有实现"与"接管新增加固"，信息不足，且两种口径可能给出相反的采用结论。
2. **用 `Δ_actual` 判定、只把分母换成 `D_pre`。** 未采用：`Δ_actual` 计入 `D_hardening`，会使 `Δ_conservative <= 0` 那条在有脚手架删除量时照样通过——等于没有收紧。
3. **把 H 阶段新增的加固一律视为"脚手架"，删除额完全不计。** 未采用（虽然更保守）：`samlguard` 之类是独立上线、放弃 authcore 也必须保留的安全实现，删除它**确实**减少了 PSP 的维护负担；完全不计会把真实收益抹掉，也会让 `Δ_actual` 失去意义。
4. **以"删除整个文件"作为职责转移的标志。** 未采用：GeoIP 一类包装是从较大实现变成较小适配器，文件仍在、方法体缩小，同样可能是净减；反之移动文件不是减少职责。
5. **把 authcore 的代码规模计入 PSP 的维护负担。** 未采用：衡量的是 PSP 自维护的行数。但这不意味着可以忽略依赖成本——它按第 6 条单列。
6. **要求实验必须得出 adopted 才算完成。** 未采用：见"背景"——ADR 3 的退出标准和 `audit`/`clientip` 的先例都表明"不采用"是合法且有价值的结论。

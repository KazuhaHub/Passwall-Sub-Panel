# ADR 0038：被拒绝的节点上报是一个要记录、要判定、要显示的事实

- 状态：已接受
- 日期：2026-09-22

## 背景

节点每轮主动上报。当上报的 wire 代际超出面板已审核范围时，面板在 HTTP 边界拒收并返回 400。
在此之前，**拒绝之后什么都不发生**：

- `UpdateProtocolObservation` 在 `Sync` 内部，远在闸门之后，所以 `observed_protocol_version` /
  `observed_capabilities` / `protocol_observed_at` 三列仍然停留在**最后一次被接受**的上报上；
- `last_seen` 只由 `RecordApplied` 写，位置更靠后；
- 审计中间件不匹配 `/v1/node/sync`；
- 该路由上没有任何结果计数器。

于是服务器列表在离线对账窗口（默认 30 天）内持续显示 `compatible`，远程升级入口是亮的，而每一轮
上报都在被回 400。窗口过后退化为 `unknown`，提示语是"尚未保存通过身份验证的协议上报，请等待节点
成功连接一次"——节点一直在连、一直被拒，这句话是假的；而且 `unknown` 正是一台从未安装过的服务器
所在的格子。

**"节点代际超前"、"节点上报损坏"、"节点已停机"在界面上是同一种样子。** 唯一写着真实原因的那句话
被投递给了节点，进了节点自己的 journal。

## 决策

### 1. 拒绝记录与观察记录互斥，守卫不因此放宽

新增 `refused_protocol_version` / `refused_reason` / `refused_first_at` / `refused_at` 四列，与
观察三列**不共用**。

把被拒代际写进 `ObservedProtocolVersion` 看起来更省，是错的：观察列记录的是面板**接受过并仍在据以
行动**的事实，覆盖它等于销毁面板对这个节点唯一还确知的东西，而 compat-policy §3.2 的
「控制端失联时保留最后有效配置」正是指这条记录。`canonicalProtocolCapabilities` 也会拒绝超范围
取值，所以这种写入只会失败，不会静默损坏——这四列的存在是为了让这个事实**有个正确的去处**。

该守卫的上界随之改读 `domain.SupportedNodeProtocolGenerations()`（见 ADR 0033 §1 与
`passwall-protocol` 的 `GenerationRange`），不得为了容纳被拒值而放宽。

`refused_first_at` 用 `COALESCE` 只在一轮拒绝的**第一次**写入，所以每 30 秒重试一次的节点不会把
运维看到的"自何时起"不断刷新。接受一次上报即清空全部四列：拒绝是当前事实，不是粘性标记——与
能力撤回同一条规则（ADR 0033 §2）。

### 2. `refused_at` 不是 `last_seen`，这不是命名洁癖

`last_seen` 是最顺手也最危险的落点。它有三个既有消费者：

| 消费者 | 读它来决定 | 写进去的后果 |
| --- | --- | --- |
| `internal/service/nodehealth` | agent 是否离线（离线时抑制告警） | 被拒节点从"离线"翻成"在线"，然后拿**冻结的**主机指标去撞阈值 |
| 节点安装视图 | 是否仍在 applying | 状态机被一个根本没建立通话的节点推进 |
| 服务器列表 | 最近活跃时间 | 显示"刚刚活跃"，而面板从未收下它任何一句话 |

拒绝说明的是"这一轮通话没有成立"，不是"这台机器还活着"。两者必须分开记。

### 3. 拒绝在判定模型里优先于观察，且不可 force 豁免

`compatadmission.Request` 增加 `Refused`。它在**无观察分支之前**求值：一台从未被接受过、但此刻正
在被拒的节点，绝不能落进"对它一无所知"那一格——那正是从未安装的节点所在的格子，把两者做成同一种
外观就是本 ADR 要终结的缺陷。

它也在 `Force` 之前求值，理由与协议分支相同：运维确认"证据薄弱"不能使面板变得**读得懂**一份它读不
懂的上报。

**不得把拒绝折叠进 `Observation`。** 那样更整洁，且会在一个特定时刻炸开：放宽代际范围的那次发布，
正是修好这个配对的那次发布；同一条记录届时会**穿过**协议分支落进能力分支，携带数周前的能力集合，
把节点报成缺少它从未失去的能力——冒号后面空无一物——而那句话正是升级路径交给运维的拒绝理由。

### 4. 代际拒绝判 `incompatible`；其余的判 `limited`

- **代际超出已审核范围** → `incompatible` / `protocol-incompatible`。ADR 0033 §4 对 `incompatible`
  的定义是**条件式**的，而这就是它的条件：协议版本超出当前已审核范围、阻止远程升级。
- **其他任何结构性拒绝**（字段缺失、枚举非法、partial 报文携带全量枚举……）→ `limited` /
  `report-refused`。配对可能完全没问题，只是这份上报读不了；宣称"不兼容"比证据更强。`limited` 是
  ADR 0033 §4 的"继续服务、动作需人工"，正是这台节点的处境。

**绝不判 `unknown`。** 那是"从未安装"那一格。

### 5. 措辞按"非故障"约束写，并承认这条只由措辞承担

compat-policy §4.1 要求状态不可互相代换，`:80` 要求"最后实测版本之外意味着未验证，不等于故障"。
`incompatible` 的文案因此必须写成"本面板尚未审核该代际，已拒绝同步；节点仍在按最后一次生效的配置
转发流量"，并同时给出**被拒代际**与**最后一次通过验证的代际**两个数字。

这条约束**没有类型或测试来守**：以后有人把这句话改成故障口吻，不会有任何测试失败。此处明写这个
代价，而不是假装它不存在。

### 6. 面板先按自己的声明判代际，共享校验器的字面量不动

`/v1/node/sync` 在调用 `ValidateNodeReportBase` 之前，先按 `SupportedNodeProtocolGenerations()`
判一次。两者今天一致；这道检查存在是为了让它们**不能悄悄不一致**。

共享包里 `report.ProtocolVersion > ProtocolVersion1` 那个字面量**保持原样**：按 `GenerationRange`
的规则，破坏性代际要开并行端点，那个字面量正是未来 `/v2/node/sync` 应当在其旁边建立的东西，不是
该被放宽的东西。

## 后果

- 升级数据库新增四列，旧行为 NULL，语义为"从未被拒"，无需重新添加服务器。
- `/v1/node/sync` 有了第一个结果计数器 `psp_node_sync_refused_total{reason}`。日志按 agent 节流
  （与主机遥测掉样同一套），**计数器不节流**——它是持久记录。
- 判定对**每一个** agent 求值，不再只对有已接受观察的 agent 求值。这是使关键情形可达的那一步。
- 行上同时携带"最后接受的代际"与"被拒代际"，compat-policy §3.2 第一次在界面上可见，而不只是成立。
- 前端按 `node_compatibility_reason` 选择文案。该字段后端一直在发，此前无任何读者。
- **一台合规的 Passwall-Node 永远不会产生被本面板拒绝的上报。** `internal/agent/sync.go` 在发送前
  调用 `protocol.ValidateNodeReport`，而它是 `ValidateNodeReportBase` **加上**主机子树——是面板
  收报时所用规则的超集。两端从同一个模块编译同一个校验器，所以节点会先拒绝自己的报文，根本不会
  发出。

  这不是缺口，是一条安全属性，而且它准确说明了这条路径**到底为谁存在**：一个按**不同**共享模块
  代际构建的对端（也就是本 ADR 要让其可见的反方向 skew）、一个第三方的契约实现、或者一个把自己
  声明范围收窄到低于机队现状的面板。

  记录器覆盖**全部** `ValidateNodeReportBase` 失败而不只是代际分支，理由也要据此修正：**不是**
  "帮零个节点与帮每一个节点的分界"（一台合规节点两种都不会触发），而是让这条路径在**任何**上报
  被拒时都留痕，无论发报方是超前的节点、第三方实现，还是一个行为异常的客户端。
- 本 ADR 只产生 `wire-contract` 证据，**不构成** dataplane 证据，也**不构成**反方向（新 PN × 旧 PSP）
  支持承诺。compat-policy §9「六类里今天只有三类有实例」在此之后**仍然成立**。

## 考虑过但未采用的方案

- **把被拒代际写进观察列**：销毁面板唯一确知的事实，且被落库守卫拒绝。
- **用 `last_seen` 承载"我见过它"**：见 §2 的三个消费者。
- **把拒绝折叠进 `Observation`**：见 §3，在放宽范围的那次发布上炸开。
- **把 400 改成 426 或在响应体里加字段**：节点侧把任何非 200 收敛成同一个无类型 error，在场节点
  没有一台能看出区别；这是 PSP 在契约模块之外单方面改变线上行为，换不到任何可达的收益。
- **只记录代际拒绝**：会让第三方实现与行为异常客户端造成的拒绝继续隐形，而这两类恰恰是这条路径
  唯一真正的发报方。
- **把结构性拒绝也判 `incompatible`**：宣称超出证据；配对可能是好的。

# ADR 0040：线路级 Region 与 Tags

- 状态：已接受，已实现（2026-11-16，所有者批准实现）；自动化验证通过，已同步到重建的手测环境，真实浏览器检查未完成，见文末“实现与验证”
- 修订：决策第 2 条中“线路值不参与分组 `tag_filter`”及不变量 1 已由 [ADR 0041](0041-line-visibility-by-group-filter.md) 修订（2026-11-16）：线路值开始以只收窄的方式影响订阅可见性，其余不变
- 关联：[ADR 0039](0039-vless-route-lines-v2.md)、[VLESS 路由线路（V2）](../vlessroute-v2.md)

## 背景

节点的 Region 与 Tags 目前同时承担两类职责：

1. **授权**：分组 `tag_filter` 与 allowlist 资格判定（`internal/service/group`）决定用户挂载到哪些节点、
   获得哪些凭据；
2. **订阅展示与选择**：国旗前缀、`proxy_group_members` 的 `region:` / `tag:` 动态集合、模板
   `@region:` / `@tag:` 占位符、规则集成员预览的候选目录与校验。

中转线路与 VLESS 路由线路在渲染时展开为独立代理条目，但一律使用父节点的 Region 与 Tags。管理员需要
为单条线路标注不同的地区或标签，例如经过广州移动入口的中转，或经由美国出站的 VLESS 路由线路。

线路与父节点共用同一个入站及 client，凭据不能按线路单独授予。

## 决策

### 1. 线路持有自己的值，新建时复制节点值，之后完全独立

- `domain.RelayLine` 与 `domain.VlessRouteLine` 各自新增 `Region` 与 `Tags`。直连线路继续使用节点值。
- 新建线路时，编辑器以主节点当前的 Region 与 Tags 预填，管理员可修改；接口对未提供这两个字段的新线路
  取节点本次保存后的值。
- 保存后两者互不影响：修改节点不改变线路，修改线路不改变节点。渲染不做任何运行时继承，不提供
  “继承节点标签”开关。

### 2. 线路值只用于订阅展示与选择，不参与授权

线路的 Region 与 Tags 只进入渲染管线：国旗前缀、`node_set` 的 `region:` / `tag:`、模板占位符、
规则集成员预览的候选目录与“无匹配”校验。渲染层通过 `renderItem` 的统一方法读取条目生效值，不直接读取
`item.node.Region` / `item.node.Tags`。

以下内容**不读取**线路值，保持只看节点：分组 `tag_filter`、allowlist 资格、用户挂载与凭据下发、
流量统计、风控的中转地址排除、3X-UI 路由规则及 Passwall Node 协议。线路排序仍紧随父节点，节点顺序
由节点页的 `sort_order` 决定，线路 Region 不参与排序。

### 3. 旧数据按字段存在性幂等回填

启动时扫描 `nodes.relays` 与 `nodes.route_state`。对 JSON 中**缺少** Region 或 Tags 键的线路，填入该节点
当时的对应值，并以原列内容做比较交换写回，并发启动时冲突即报错重试。新版本写入时始终输出这两个键，
空值也写出，因此“键存在而值为空”表示管理员明确清空，不再回填。

这保证升级后订阅输出与升级前逐字节相同；回退到旧版本后由旧版本写回的行，再次升级时也能补齐。

### 4. 接口缺省字段不清空已有值

API 中两字段可省略：

| 请求 | 已有线路 | 新线路 |
| --- | --- | --- |
| 省略字段 | 保留已保存值 | 取节点本次保存后的值 |
| 显式 `""` / `[]` | 清空 | 为空 |

这防止升级后仍打开着的旧页面在整组提交时抹掉线路值。“未提供”只是请求解析期的临时标记，不序列化；
存储层拒绝写入仍带未解析标记的线路，遗漏解析步骤会直接失败而不是静默清空。

规范化与节点一致，不改变大小写：去除首尾空白，标签去空、去重并保持顺序。线路字段有上限：Region 不超过
64 字节，标签不超过 32 个，每个不超过 64 字节。

### 5. VLESS 路由线路的展示信息可离线保存

展示字段为：名称、仅显示线路名称、Region、Tags。它们只影响 PSP 内部的订阅展示，不进入 3X-UI 路由规则。

满足以下全部条件时，保存走纯本地路径，不连接 3X-UI：

- 提交的线路与已保存的未删除线路 ID 和顺序完全一致，没有新增或删除；
- 规范化后，除展示字段外每个字段都与已保存值相同；
- 至少一个展示字段发生变化。

本地路径仅依据本地记录确认功能适用（3X-UI 后端、VLESS 节点），然后持有同一后端的本地租约、校验
revision，保留 `status` / `error` / `binding` 不变，写库并失效订阅缓存。

完全没有变化的保存仍走原流程，以保留“重新保存以重新确认”的行为；同时修改了规则相关字段的保存也走
原流程。展示字段由 domain 中的单一函数界定；以后新增的线路字段默认按规则相关处理，只有显式加入该函数
才能离线保存。

中转线路通过节点元数据接口保存，本来只写本地数据库，不受本条影响。

## 后果

- 修改节点 Region 或 Tags 后，已有线路不再随之改变。依赖 `tag:` / `region:` 的代理组需要管理员逐条
  核对线路值。节点编辑界面需明确提示这一点。
- 线路的国旗按线路自己的 Region 生成，替代 VLESS 路由线路 V2 文档中“国旗按父节点 region”的说明。
- 升级不需要管理员操作，订阅输出不变。
- 回退：旧版本会忽略这两个字段，并在保存节点或路由时丢弃它们。再次升级后，这些线路回填为节点当时的值，
  而不是此前自定义的值。
- 已确认（applied）状态的 VLESS 路由线路，离线修改展示信息后状态保持 applied。远端规则没有因此改变，
  漂移仍由既有巡检发现。

不能破坏的不变量：

1. 授权路径不读取线路值；
2. 未提供的字段不清空已有值；
3. 离线路径不改变任何规则相关字段及应用状态。

## 考虑过但未采用

- **渲染时继承（空即继承）或提供继承开关**：所有者选择独立语义。继承会让一次节点修改隐式改变多条线路
  在代理组中的归属，难以预期。
- **线路标签参与分组 `tag_filter`**：线路共用入站 client，无法按线路授权，会出现“分组匹配到线路但用户
  未被授权”的矛盾。
- **按线路 Region 重新排序**：节点顺序由节点页 `sort_order` 决定，线路紧随父节点，避免客户端列表大幅
  变化。
- **带完成标记的一次性迁移**：回退再升级后，无法补齐旧版本写回、缺少字段的行；改用按键存在性判定的
  幂等回填。
- **所有改动都可离线保存，或远端失败时回落本地**：会让规则改动绕过入站与模板校验。

## 实现与验证（2026-11-16）

实现位置：

- domain：`internal/domain/line_labels.go`（规范化与上限、省略字段解析、存储前检查、展示字段的唯一界定 `splitRouteLineDisplay` / `CompareRouteLineDisplay`）；`RelayLine` / `VlessRouteLine` 新增 `Region`、`Tags` 及不序列化的 `RegionUnresolved` / `TagsUnresolved` 标记。
- 存储：`jsonRelays` / `jsonRouteState` 写入前拒绝未解析标记并总是写出两个键；`backfillLineLabels`（`internal/adapters/sqlstore/node_lines_migration.go`）按键存在性做幂等回填，逐列比较交换。
- 接口：节点元数据接口的 `relays[].region/tags` 为可省略字段，由 `node.Service` 在中转 ID 对齐之后解析（新建、纳管路径在入队前解析）；VLESS 路由线路 `LineInput.region/tags` 同理，在 `makeTarget` 中解析。
- 离线路径：`vlessroute.saveDisplayOnly` 先用本地记录判断适用性，再持本地租约、校验 revision 后写库并失效订阅缓存；不满足条件时交回原远端流程。
- 渲染：`renderItem.region()` / `tags()`，国旗、占位符、`node_set` 成员、候选目录与“无匹配”校验均经此读取；候选目录的线路条目附带各自的 Region / Tags。
- 前端：中转与 VLESS 路由线路编辑器增加 Region、Tags（新建时以节点表单当前值预填）；节点存在线路时，节点 Tags 下方提示修改节点不影响已有线路；未加载到标签的旧线路提交时不携带这两个字段。

不变量守护：

1. `internal/domain/line_labels_guard_test.go` 以 `go list -export` 加 `go/types` 类型检查全仓，`RelayLine` / `VlessRouteLine` 的 `Region` / `Tags` 只允许出现在 domain、render、vlessroute、sqlstore 与 `admin_node.go`；在 group 包注入一次读取、从白名单移除 render 两种变异均被检出。
2. 省略字段保留已存值：domain、节点服务（含旧客户端无 ID 的匹配路径）、VLESS 路由服务、HTTP 解析及前端提交均有对应测试；存储层拒绝未解析标记。
3. 离线路径：测试断言不发生任何 3X-UI 调用（状态、模板、入站读写计数不变），`status` / `error` / `binding` 不变（含 `drift`），revision CAS 与租约冲突时拒绝；无变化保存、规则字段变化、增删线路、调整顺序均走远端流程。展示字段集合由反射测试锁定，新增字段默认属于规则相关。

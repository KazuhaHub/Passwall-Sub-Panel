# ADR 0041：线路按分组筛选条件决定订阅可见性

- 状态：已接受，已实现（2026-11-16，所有者批准实现）；自动化验证通过，已同步手测环境，见文末“实现与验证”
- 修订：[ADR 0040](0040-line-region-and-tags.md) 决策第 2 条中“线路值不参与分组 `tag_filter`”及不变量 1；其余决策不变
- 关联：[ADR 0039](0039-vless-route-lines-v2.md)、[VLESS 路由线路（V2）](../vlessroute-v2.md)、[ARCHITECTURE §6.3、§7.6](../ARCHITECTURE.md)

## 背景

ADR 0040 让中转线路与 VLESS 路由线路持有独立的 Region / Tags，但只用于订阅展示与选择：用户分组只要
满足节点的 `tag_filter`（及 allowlist 资格），该节点的全部线路就进入订阅。管理员需要按分组决定某条线路
是否下发，例如广州移动中转只给特定分组。

ADR 0040 否决“线路标签参与分组 `tag_filter`”，理由是线路共用入站 client，无法按线路授权，会出现
“分组匹配到线路但用户未被授权”的矛盾。若线路条件只在节点条件之上进一步收窄，该矛盾不会出现：
不满足节点条件的分组本来就看不到任何线路。

所有者确认：

1. 不新增“可见分组”字段，直接使用线路已有的 Region / Tags；
2. 线路值与节点值设计上独立，修改节点不同步线路，需要分别修改；
3. 统一在一处筛选；创建/编辑时冲突只提醒、不拒绝；接受展示信息离线保存会改变可见性。

## 决策

### 1. 可见性只收窄：节点条件 ∧ 线路条件

某分组的用户能在订阅中看到一条线路，当且仅当：

- 该分组满足节点条件：`group.Service.Eligible(node, group)`，即 `tag_filter` 与 allowlist 资格，
  语义完全不变；并且
- 该分组的 `tag_filter` 以线路自己的 Region / Tags 求值也为真。

直连条目使用节点值，因此等价于只看节点条件。线路条件永远不能让一个不满足节点条件的分组看到线路。

### 2. 线路条件复用同一套匹配语义

线路求值使用与节点完全相同的 `tag_filter`：`All` 恒真，`Mode` 为 all / any，条件逐项解析。
仅替换取值来源：

| 条件 | 节点求值 | 线路求值 |
| --- | --- | --- |
| `region:XX` | 节点 Region，不区分大小写 | 线路 Region，不区分大小写 |
| `tag:yy`、无冒号、其他 `key:value` | 节点 Tags 精确匹配 | 线路 Tags 精确匹配 |
| `node:addr` | 节点 `ServerAddress` | 仍为节点 `ServerAddress`（线路没有该标签） |

实现位于 `internal/service/group`，以节点副本替换 Region / Tags 后调用同一个 `matchOne`，
不另写匹配逻辑。allowlist 资格只按节点判断，线路不参与。

### 3. 路由线路的入口连带判断

选择了中转入口（`entry_relay_id`）的 VLESS 路由线路，只有在入口中转对该分组也可见时才可见。
入口不可见时路由线路不下发，不回退直连，避免经由路由条目暴露被隐藏的中转地址。直连入口不受影响。

### 4. 统一筛选一次

在 `expandNodeLines` 之后、发布过滤、国旗、成员解析之前，按用户分组一次性移除不可见线路。
之后所有路径只消费筛选后的集合：

- Mihomo、sing-box、URI 链接订阅；
- 规则集成员预览（按分组预览）；
- 成员选择的“按节点选择”“按线路选择”“按区域匹配”“按标签匹配”“其余线路”，以及模板
  `@all` / `@region:` / `@tag:` 占位符；
- 用户状态页 `/api/user/me` 的线路列表（与订阅共用同一判断，不得各自实现）。

不提供分组上下文的后台候选目录（规则集编辑器）继续列出全部线路，“无匹配”校验口径不变。
被筛除的“按线路选择”引用视同不可用线路，沿用现有“不可用目标不回退、不改指其他线路”的处理。

### 5. 冲突只提醒，不拒绝

“冲突”指：所有满足节点条件的分组中，没有任何一个能看到该线路。

- 新增只读接口，按草稿中的线路 Region / Tags 计算每条线路对哪些分组可见（只在满足节点条件的分组中
  计算），不写库、不写审计；
- 节点编辑器在线路旁显示可见分组；为零时提示，保存不因此被拒绝；
- 分组读取或 allowlist 资格读取失败时返回错误或“未知”，不得显示为“无分组可见”或“全部可见”。

分组条件之后仍可能变化，因此以编辑器的实时结果为准，不在保存时固化。

### 6. 这不是访问控制

线路共用节点的入站与 client：中转线路只替换连接地址，VLESS 路由线路只改变已应用 UUID 的第 7–8 字节
（路由值可推测）。被筛除的用户若自行改写连接参数，仍可使用这些线路。本决策只决定订阅是否下发，
界面与文档须与“隐藏直连线路”一样写明不是网络访问控制，不撤销已下载的配置。

### 7. 对 ADR 0040 的修订

- 线路 Region / Tags 除展示外，开始影响订阅可见性；仍不进入凭据下发、挂载、流量、风控、3X-UI 路由规则
  及 Passwall Node 协议。
- 不变量 1 改为“除 `internal/service/group` 的线路可见性判断外，授权路径不读取线路值”；
  `line_labels_guard_test.go` 的白名单仅增加该包，作为本次决策的显式记录。
- 展示信息离线保存（ADR 0040 §5）保持本地路径与状态不变，但会改变可见性；保存后失效订阅缓存
  （已有行为），后台提示文字相应调整。

## 后果

- 默认行为不变：线路新建时复制节点值，旧线路由回填补齐，因此在线路值未被单独修改前，可见性与节点相同。
  ADR 0040 上线后已被单独修改的线路，升级后可能对部分分组隐藏。
- 修改节点 Region / Tags 以纳入新分组时，已有线路不会随之可见，需要逐条修改线路值；编辑器的可见分组
  显示用于发现这类情况。
- 订阅渲染、分组预览与用户状态页多一次按分组的线路判断；判断只读内存中的节点与分组，不访问远端。
- 规则集中“按线路选择”引用的线路对某分组隐藏时，该分组的代理组少一个成员；空组按既有规则处理。

不能破坏的不变量：

1. 线路条件只收窄，不放宽节点条件；
2. 所有订阅格式、预览与用户状态页使用同一筛选结果；
3. 可见性判断失败不得被当作“全部可见”或“全部不可见”；
4. 线路值仍不进入凭据、挂载、流量、风控、3X-UI 路由规则与 Passwall Node 协议。

## 考虑过但未采用

- **独立的“可见分组”字段**：所有者选择沿用 Region / Tags，避免新增一套需要维护的线路配置。
- **线路值随节点同步或空值继承**：与 ADR 0040 的独立语义冲突，节点修改会隐式改变多条线路的可见性。
- **各成员选择方式分别检查**：其余线路、模板占位符、URI 链接订阅等路径容易遗漏，导致隐藏线路泄漏。
- **创建时冲突即拒绝**：分组条件会在之后变化，拒绝只在保存瞬间成立，且妨碍先建线路再调整分组。
- **真正的按线路访问控制**：需要以下改动，成本与风险远高于订阅筛选，暂不实施：
  - VLESS 路由线路：3X-UI 路由规则在 `inboundTag + vlessRoute` 之外增加 `user`（可见用户的共享 client
    email，含 `-c1` / `-k` 分裂 email）条件，并紧随其后增加同 `inboundTag + vlessRoute`、无 `user` 的拒绝规则，
    否则未授权流量会落到后续规则或默认出站。这要求 PSP 依赖或创建阻断出站（ADR 0039 只读出站），且每次用户
    启停、改组、删除、分组条件或线路值变化都要重写整份模板并重启 Xray，需要接入 `ResyncMembership`、
    分组变更与同步任务重试，并把 Region / Tags 改为规则相关字段（ADR 0040 的离线保存随之取消）。
  - 中转线路：入口只是外部转发到同一入站端口，PSP 无法区分来源。真正控制需要把每条中转变成独立入站，
    只为可见用户挂载 client，连带改变挂载表、凭据下发、流量统计、对账、健康检查与节点删除流程；
    或依赖中转出口 IP 加 `user` 条件的来源规则，脆弱且无法覆盖 NAT 变化。
  - S-UI 与 Passwall Node 目前没有线路概念，需要协议与适配器扩展、能力声明及兼容证据。
  - 已下载订阅、已撤销用户的生效时延与“未知不显示为通过”的状态展示均需重新设计。

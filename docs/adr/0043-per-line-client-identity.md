# ADR 0043：每条线路一个客户端身份（按线路计费倍率）

- 状态：已接受（2026-11-16，所有者批准）；实现于 4.3 开发分支，合入时间在 4.2.0 正式版之后
- 关联：[流量倍率](../traffic-multiplier.md)、[托管中转](../transit-lines.md)、
  [ADR 0040](0040-line-region-and-tags.md)、[ADR 0041](0041-line-visibility-by-group-filter.md)

## 背景

所有者要求按线路设置流量倍率：节点的直连线路和它的每条中转线路各有一个倍率，经过这条线路的流量
一律按这条线路的倍率计费，“设置的什么，不管如何经过谁，都按设置的来”。

4.2 之前，用户在一台服务器上只有一个（或按密码类别拆出的少数几个）共享客户端，挂在该服务器所有
入站上。中转线路只把连接转到落地的入站，落地看到的是同一个客户端、同一个计数器，无法区分一个字节
走的是直连还是哪条中转。倍率要按线路生效，线路就必须有自己的计数器。

## 决策

### 1. 一条线路一个客户端行

- `psp_clients` 每行对应一个（用户，线路）：新增 `node_id`、`line_id`（直连为 `direct`，中转为
  `RelayLine.ID`），唯一索引 `(user_id, node_id, line_id)`；两列为 NULL 的是 4.3 之前的旧行。
- 每行只挂一个监听器：直连与中转线路挂在落地节点的入站上（中转把连接转到这里）；有自己监听器的线路
  挂在那个监听器上。规划器（`clientplan.Build`）不再合并分区。
- 只为用户可见的线路建行（`group.ClientLinesFor`：分组包含的节点，按 ADR 0041 收窄线路；隧道未就绪
  的节点仍保留行，只是暂不发布）。线路新增、删除或标签变化时，节点所属分组的成员重新规划。

### 2. 身份

- **直连线路**沿用用户自己的 UUID 和原有密码类别，与此前渲染的凭据逐字节相同：只用直连线路的用户，
  订阅不变。唯一例外是以客户端邮箱为用户名的 Naive 与 WireGuard：同一服务器上除最小 ID 节点外的直连
  线路需要各自的邮箱（面板内邮箱唯一），这些线路的用户名会变化。
- **其他线路**使用派生 UUID：`HMAC-SHA256(key = 用户 UUID, "psp-line-v1\x1f" + nodeID + "\x1f" + lineID)`
  取前 16 字节，按随机 UUID（v4、RFC 4122 变体）设置版本与变体位。密码按协议类别由该行自己的 UUID
  生成（SS-2022 的 PSK 也因此每条线路不同）。派生值存入行中。
- **同一监听器上唯一**：比较时去掉连字符、转小写并屏蔽第 6–7 字节（`domain.LineUUIDKey`，列
  `uuid_key` 带索引）。与该监听器上其他客户端冲突时，在消息末尾加 `#2`、`#3`… 重新派生；行自己当前
  持有的值不算冲突。用户重置 UUID 时，所有派生身份随之变化。
- **邮箱**：已有行保留原邮箱；新行为 `u{uid}-l{sha256("{nodeID}|{lineID}") 前 10 位十六进制}@{域}`。
  共享客户端识别（`IsSharedClientEmail`）接受 `-l` 后缀。

### 3. 计费与执法

- 轮询按每行自己线路的倍率记账（`domain.ClientTrafficFactor`）；线路已删除时用该行上次记账的倍率
  （`last_factor_milli`），旧行按 1:1。
- 离线额度按行换算：PN 每行 `floor(剩余计费字节 × 1000 / f)`，f=0 时有剩余不设闸、用尽为 0；下一周期
  `limit × 1000 / f`。3X-UI / S-UI 每个客户端按其线路倍率经 `domain.RawHeadroom` 换算。每行都拿到用户的
  全部剩余额度，面板不可达期间超用有界（与此前按服务器扇出相同的性质）。

### 4. 线路删除

用户失去一条线路时，该行只解除挂载，不立即删除：它的计数器可能还有未记账的流量。轮询在一次成功
读取其服务器、并把该周期的计数与用户账本写入之后删除这些行（新建不足一分钟的行除外，规划器建行与
挂载是两次写入）。

### 5. 渲染

- 订阅按线路取“已应用”的凭据：中转线路使用自己已应用的身份。
- 中转线路的身份尚未应用时，直接转发与外部中转线路暂用直连身份（落地监听器同样接受），按直连线路
  的倍率记账；有自己监听器的线路在应用前不发布。

### 6. 来源 IP

直接转发与外部中转线路的客户端，落地看到的是中转的地址，这些地址不计入个人的 IP 数与地理位置判断；
直连和有自己监听器的线路照常计入。

### 7. 升级

`schema_upgrade_v4_3.go` 在升级时自动完成（所有者确认 4.2 未配置任何倍率，不提供迁移界面）：旧共享行
成为其最小 ID 节点的直连行（保留 ID、邮箱、计数），其他直连线路以同一 UUID 新建行，中转线路使用派生
身份。3X-UI / S-UI 上需要的拆分与新建由升级后的正常生命周期完成。

## 后果

- 客户端数量从“每用户每服务器 1 个”变为“每用户每可见线路 1 个”。服务器上的身份接近同步预算时给出
  警告；不依赖协议侧正在增加的压缩同步能力。
- 3X-UI 的 IP 数与设备数上限按客户端计算，线路越多，实际可用上限越大（×N），界面在原有判定旁显示倍数。
- 不变量：
  1. 直连线路的身份永远是用户 UUID；只用直连线路的用户订阅逐字节不变（Naive / WireGuard 的用户名除外，
     见决策 2）。
  2. 派生身份只由用户 UUID 与线路决定（加冲突序号），改动派生规则等于为所有中转用户换身份。
  3. 一行的计数器只属于一条线路；倍率只在记账时应用一次。

## 考虑过但未采用的方案

- **按服务器设置倍率**（4.3 第一版设计）：同一服务器上的直连与中转无法区分，不符合“设在哪就按哪算”。
- **在中转服务器上计量**：直接转发不解开用户协议，只能得到线路总量，无法归到用户。
- **按入口地址或端口区分同一客户端的流量**：核心只按客户端统计，没有可靠的按入口计数。
- **升级时提供逐服务器的迁移操作**：所有者确认 4.2 未配置倍率，自动迁移更简单，且不留中间状态。

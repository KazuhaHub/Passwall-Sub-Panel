# authcore 迁移：部署兼容清单

本文件是 SAML 加固线（H）与替换线（M）的**部署前提与回滚边界**清单，供上线前逐项核对。设计理由见 [ADR 0036](adr/0036-saml-pre-migration-hardening.md)、[ADR 0037](adr/0037-authcore-shareability-experiment.md)；验收用例见 [authcore-migration-plan.md](authcore-migration-plan.md) §10。

**本清单不表示任何一项已经验证。** 每项在实施记录中填实际证据位置，未验证项明确标注，不用"看起来一致"代替验证。

## 1. 支持范围声明（必须照此对外表述）

| 能力 | 本轮声明 |
| --- | --- |
| SAML（H2 及之后的 M1） | **单实例**。持久化控制保护单实例重启；不构成多实例可用的证明。 |
| Passkey（H3 及之后的 M2） | **单实例 / 原有部署条件**。挑战仍为进程内存储，重启会中断在途操作。 |
| 多实例无粘性登录 | **不承诺。** 补齐 §4 的 HA1–HA4 之前维持上述结论。 |
| GeoIP（G1） | 独立实验，不阻塞其他包；结论可为 not_attempted。 |
| 验证码（C1） | 默认 deferred，不发布。 |
| OIDC | 本轮不实施，仍在 PSP。 |

同时满足"共享数据库 + 配置看起来一致"**不是**多实例可用的替代验证。

## 2. 新的上线前提：外部入口必须同源且为 HTTPS

浏览器绑定 Cookie 使用 `SameSite=None; Secure`（ACS 是跨站 POST，`Lax` Cookie 不会随该 POST 发送）。由此产生的硬性前提：

- [ ] 正式公共 **Login URL** 可确定（由配置的公共基址 + `panel_path` 推出，不是请求里的 Host）。
- [ ] 它与配置的 **ACS URL 同源**。
- [ ] 两者**均为 HTTPS**。
- [ ] 自定义代理回调场景下，Cookie 的 `Path` 用**外部**真实路径，不是路由分发器已剥离的内部路径。
- [ ] 代理场景经既有信任链判断，不信任任意 forwarded header。

不满足的部署**先统一正式入口**，再启用新流程。跨域 ACS 不能靠扩大 Cookie Domain 或关闭绑定来兼容；复杂跨域认证另立协议设计。

## 3. 上线前核对（每次切换都执行）

1. [ ] 保存可恢复的数据库备份与上一版本制品；记录当前 schema、配置版本、依赖版本。
2. [ ] 上线 M 之前**额外**保留对应 H 的源码 SHA、可部署制品、制品摘要，以及**已完成的回滚演练**记录（不能只有 B0 制品）。
3. [ ] 用测试 IdP/测试账户确认：外部 Login/ACS 的 HTTPS 与同源、Destination、实际签名算法、NameID 稳定性、是否使用加密断言、Metadata 刷新是否正常。
4. [ ] 自定义回调单独确认 Cookie 的外部 Path。
5. [ ] 确认一个**现有本地管理员恢复入口**可用（沿用既有账户策略）。不为迁移新开公共后门；注意该入口同样依赖数据库，**不是全库故障时的保证后门**。
6. [ ] 真实浏览器验证跨站 POST、非根 `panel_path`、代理部署；至少覆盖当前支持的 **Chromium 与 WebKit**。
7. [ ] 新的认证错误分类可观察、日志脱敏；密钥与 IdP 样本不提交到仓库。
8. [ ] 运行第 6 节的管理自检，先发现静态入口问题，无需尝试一次真实 SSO 登录。

## 4. 多实例：宣布可用前必须补齐的证据

缺任何一项即维持 §1 的单实例结论。

| 编号 | 必须新增的端到端验证 |
| --- | --- |
| HA1 | 同一外部 HTTPS origin：Login 路由至 A、真实 IdP 回调路由至 B，共享请求/replay 表，Cookie/账户/JWT 全链路成功 |
| HA2 | 两个 ACS 实例同时消费同一请求/断言；A 在发起后重启或下线：最多一次签发，正确区分可恢复与已消费失败 |
| HA3 | 从 A 修改/关闭 SAML、变更角色规则/密钥、Metadata 轮换：B 按已定义时限看到变更，**旧快照不能继续接受本应失效的请求** |
| HA4 | LB 非粘性、可信代理、时钟差、统一配置/密钥与版本切换：运行行为与运维流程都验证；混合旧版本入口不会绕过绑定 |

**HA3 目前没有实现跨进程配置传播**，因此只补 HA1 的固定配置 happy path 不足以宣布多实例可用。

## 5. 两次切换与等待窗口

**B0→H 与 H→M 必须分别发布，不得合并为一次。**

| 切换 | 引入 | 等待窗口 |
| --- | --- | --- |
| B0→H | 新的 RelayState、绑定 Cookie、严格校验、请求表 | 取"在途 AuthnRequest TTL"与"部署中断言/SubjectConfirmation 最大可接受有效期 + clock skew"的**较大值** |
| H→M | 仅替换协议实现，流程协议不变 | 排空单实例在途请求即可 |

- [ ] 等待窗口**从测试 IdP 与配置确认得出**，不固定拍成 5 分钟。不能确认窗口时不声称已完成无缝安全切换。
- [ ] 未加固与加固的入口不长期混合服务：旧实例仍接受旧 RelayState，可能绕过新请求绑定。
- [ ] 旧登录页面/旧 RelayState **一律提示重新开始**，不开兼容回退。
- [ ] M1 不得改变请求表、RelayState/Cookie 格式、配置摘要算法、错误语义或 replay 保留期；若必须改，回到独立 H 修订、产生新 H 制品后**重新测量**。
- [ ] 已有多实例部署不在本轮自动升级承诺中：先完成 HA1–HA4，或按部署计划暂收敛到单实例。

## 6. 管理员自检命令（只读）

该端点是 H2 新增的**管理员专用只读** `GET /api/admin/settings/saml/preflight`，当前基线尚不存在。使用既有管理员凭证，不提供公开免认证检查。

```sh
PSP_PUBLIC_ORIGIN='https://panel.example.com'
PSP_PANEL_PATH='/panel'
# 在当前安全终端中提供既有管理员 token；不要把真实 token 写进文档或日志。
curl --fail-with-body --silent --show-error \
  -H "Authorization: Bearer ${PSP_ADMIN_TOKEN:?请先提供管理员令牌}" \
  "${PSP_PUBLIC_ORIGIN}${PSP_PANEL_PATH}/api/admin/settings/saml/preflight"
```

- [ ] 根路径部署时 `PSP_PANEL_PATH` 设为空。
- [ ] 逐个核对 `configuration_valid` 与 `checks` 枚举，不要只看 HTTP 200——**200 不代表检查全通过**。
- [ ] `checks` 中**已知缺失**（如 replay 后端未装配）应为 `failed`；只有未实际执行的验证才是 `not_checked`。
- [ ] `configuration_valid` 只表示配置合法，运行准备情况另看；两者不互相顶替。

**自检的边界**：它不证明浏览器接受 Cookie，也不证明数据库**未来**可写（当前不可写会表现为 `not_checked` 之外的运行时失败）。这些仍必须由相应验收证据覆盖。

## 7. 回滚边界

| 回滚/退出对象 | 正常目标 | 必须保留 |
| --- | --- | --- |
| M1 失败或共享收益不成立 | 已验证的 **H_SAML** 制品；源码恢复 H 引擎 | Destination/多断言/弱算法校验、请求绑定、fail-closed、配置快照、原子存储 |
| M2 失败或共享收益不成立 | 已验证的 **H_PASSKEY** 制品；源码恢复 H 引擎 | 原凭证格式、克隆拒绝零写入、撤销竞态修复、用途隔离、计数器单调性 |
| G1 不成立 | G1 自己的本地 Reader 基线 | 不影响 SAML/Passkey 是否采用 |
| H 本身有故障 | 优先暂停受影响的登录方法，修复或回滚**该独立 H 发布** | 不伪称退回 B0 没有安全损失；被撤销的保护另行记录 |

- [ ] 回滚**不 DROP** 请求/replay 表，不用旧数据库备份覆盖上线后的业务数据，不回退 Passkey 计数器。
- [ ] H 与 M 使用**相同 schema 与线上状态契约**；恢复本地引擎后用 R05 验证保护仍在。
- [ ] H 制品必须包含**待回滚版本中其他已交付的加固**。若最初的 H 制品早于后来独立发布的安全修复，**不能直接拿旧二进制回退**——应在当前发布基线上只恢复相应本地引擎，重新构建、验证并保存回滚制品。该准备在**上线每个 M 之前**完成，不在故障时临时推断。
- [ ] 源码回退不能在日后混有其他功能改动时简单执行大范围 `git revert`；应单独替换协议后端并保留 H 控制，重跑共享行为测试。
- [ ] 只要其他包仍采用 authcore，就**不能**为退出一个包删除整个模块依赖。
- [ ] 停用/切换制品后清理或等待临时 Cookie 过期；在途操作重新开始。
- [ ] **不提供**"authcore 校验失败则调用本地校验"的运行时降级开关：保留 H 制品/源码供回滚，不等于生产同时运行两套可由输入选择的认证路径。

## 8. 发布说明必须包含

- [ ] 支持范围为**单实例 SAML**；HA1–HA4 未完成即不声明多实例。
- [ ] 新增的 **HTTPS/同源**入口前提。
- [ ] 在途 Passkey 挑战与旧 RelayState **失效**，需重新开始。
- [ ] **SAML 严格校验**已生效（Destination 必填、拒绝多断言与弱签名）。
- [ ] replay 存储故障时 **fail-closed**，以及它的运维含义（见 ADR 0036 后果）。
- [ ] 安全回滚的限制：回滚到未加固版本等于撤销上述保护。

### 8.1 H1 严格校验的实际影响（上线前逐项确认）

H1 的预检在验签之前执行（`internal/pkg/samlguard`，接入 `ParseACSResponse`），上线即生效，不需要等 M1。它对现有部署有三处真实影响：

- [ ] **IdP 仍在用 rsa-sha1 的部署会立即登不进去。** ADFS 与旧版 Keycloak 的历史默认算法就是 rsa-sha1，这正是预检要拒绝的。**必须在维护窗口内先确认 IdP 当前的签名与摘要算法**，并在 IdP 侧升级到 SHA-256 以上之后再上线。摘要算法允许集来自 authcore 的白名单，只有三个：`xmlenc#sha256`、`xmldsig-more#sha384`、`xmlenc#sha512`（注意**不含** `xmlenc#sha384`）。
- [ ] **所有响应必须携带与配置 ACS URL 完全一致的 `Destination`。** 主流 IdP（Entra/Okta/Google/ADFS）都会带；自建或老版本 IdP 若省略，需先在 IdP 侧修正。
- [ ] **携带 `SAMLart` 的 artifact-binding 请求会被拒绝。** PSP 只构造 Redirect-binding 的 AuthnRequest，从不请求 artifact binding，因此这是"拒绝一个从未使用的路径"，不是能力丢失。若某个部署确实依赖它，须在 H1 上线前提出，不能默认它继续可用。
- [ ] 响应必须恰好携带一个 `Assertion` 或 `EncryptedAssertion`（加密断言仍被接受，SP 私钥可解密）。

预检的失败原因会出现在 SSO 失败页的 `description` 参数中。**其中包含收到的 `Destination` 等外部值**；把它收敛为低基数原因码属于 H2 的范围（计划书 §6.9），H1 上线时按现状记录。

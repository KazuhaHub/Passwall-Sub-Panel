# PSP v4.0.0-beta.5

这是 V4 测试版。新增统一“安装 / 重新安装”入口，以及在节点机执行的私有安装、迁移命令。
Passwall Node 继续使用已发布、登记兼容的 `v0.0.1-beta3`；本次不发布新的节点程序版本，
也不自动升级现有节点或转换服务器后端。

## 安装 / 重新安装

已有服务器默认选择原后端，新建默认选择完整名称 **Passwall Node**。可选择 Passwall Node、
3X-UI 或 S-UI；安装与内核／程序升级是独立操作。

Passwall Node 默认 Linux 二进制 + systemd，支持复制一条命令在节点机执行；精确版本必须
来自本版 PSP 核验过的发行目录。手动、Docker 和高级私有脚本下载仍保留。普通重装读取
原身份与固定凭据，不新建服务器、节点或客户端，也不以重装隐式轮换凭据。

3X-UI、S-UI 同后端重装提供官方手动步骤，并可更新**原服务器记录**的连接信息；仅更新
URL/Token 不代表入站和客户端已经恢复。暂不提供无人值守配置恢复或未经证明无损的跨后端转换。

## 3X-UI → Passwall Node：命令在节点机执行

预检仍是只读操作；确认受管范围、备份、准确 Node/Xray 版本及单 PSP 实例后，生成限时命令。
管理员不必先到 PSP 主机执行数据库转换 CLI；默认命令直接在**节点机**以 root 执行。

- 在线转换仅限**共用数据库只有一个 PSP 进程**。程序排空本实例正在进行的请求与后台写入，
  核对预检指纹，在一个事务中转换后端，并替换适配器后恢复准入；不是分布式锁。
- 自动包装器只支持标准 root-owned Linux amd64/arm64 systemd x-ui 部署，或重装系统后的
  干净 systemd 节点。先检查工具、进程、单位与路径，校验一致性备份，再停止、禁用旧服务。
  旧安装和私有备份保留，不自动卸载或回滚。容器、自定义命名空间映射、残缺安装等需手动处理。
- 原服务器、节点、客户端、挂载 ID、受管配置与已确认代理凭据、分组排序及历史流量保留。
  新 Node Agent 和加密固定安装凭据绑定到同一服务器记录；回调重试不重复创建身份。
- 下载授权 15 分钟过期、单次取用；命令 URL 不含长期 Node 凭据。独立回调授权支持限时幂等
  重试。配置变化、凭据轮换或不确定提交状态不能绕过验证；失败不假称回滚。
- 停止前必须确认没有面板／内核升级或外部自动化可能重启旧服务。仅“无法连接”不证明核心已停。

只有可完整核验的 PSP-managed Xray VLESS、VMess、Trojan、Shadowsocks 快照能转换。
外部证书文件、全局路由/DNS/出站、手工对象与未迁移依赖不自动导入；S-UI → Node 仍未开放。
多 PSP 实例及不支持的部署可使用 [停机维护 CLI](../server-migration.md)。

命令属于敏感材料，请勿分享或启用 shell tracing，注意终端历史与反向代理访问日志。
安装器退出成功或心跳在线不等于代理可用；仍须确认原服务器的配置、客户端与核心应用状态，
以及实际代理连接。

## 升级

从正常运行的 V4 升级，保留数据库、配置／环境、加密密钥和数据卷，仅替换 PSP 镜像／二进制。
本次没有新的数据库表或通用恢复工作流；升级本身不会启动节点迁移或安装。
V3/V2 的限制见 [V4 升级指南](../UPGRADE-v4.md)。Docker 测试版准确标签为
`ghcr.io/kazuhahub/passwall-sub-panel:v4.0.0-beta.5`；`latest` 继续保持正式版。

验证结果以本发行对应 PR/CI 为准：数据库全套、生产浏览器、真实隔离 systemd 安装／重装与
迁移后连接验收均须通过后才发布。隔离环境结果不替代用户服务器上的订阅、流量和代理检查。

# PSP v4.0.0-beta.2

这是 V4 的后续测试版，不是正式版。包含 Passwall Node 安装向导与已确认的历史数据库迁移收敛。Passwall Node 仍使用已发布的 `v0.0.1-beta3`，本次不发布或自动升级节点程序。

## Passwall Node 安装向导

- 新增服务器时，**Passwall Node** 排第一且默认选中，不再显示 PSP Node 缩写。
- 在同一个弹窗内选择安装方式，创建服务器后继续查看专属材料；默认 Linux 二进制 + systemd 一键安装。
- Docker 提供固定版本 Compose、非敏感环境文件及私有凭据文件，自动匹配主机架构。需要 Linux Docker Engine、Compose 2.30.0 或更高版本和 host 网络；守护进程仍以非 root 运行，不挂载 Docker socket、不使用特权容器。
- 手动安装支持 Linux/macOS/Windows × amd64/arm64，提供准确版本下载、SHA-256 校验、解包、私有凭据和前台运行步骤。Windows 使用 PowerShell 5.1 + .NET Framework 4.7.2 或更高版本，或 PowerShell 7。
- 切换安装方式或重新打开安装窗口不会重新创建服务器、改变 Agent ID 或轮换固定凭据。代理节点/inbound 仍在节点页面单独添加，心跳不等于代理内核已运行。

安装材料含长期凭据，仅供管理员私密读取、复制或下载；不要分享、放进命令参数/日志或提交 Git。原 Linux 脚本和新材料接口在释放秘密前均须成功写入不含秘密的读取审计，且禁止缓存。

Docker 材料补齐现有 Node 镜像入口初始化私密文件所需的权限；不修改已发布的 Node 镜像。Docker 由主机通过 Compose 管理更新，手动方式以前台运行、不注册系统服务或远程升级助手；Linux/systemd 的远程升级入口保持独立。

## 升级到 beta2

升级前保留匹配的完整数据库、配置/环境、原密钥及旧镜像或二进制。仅替换 PSP 镜像/二进制，保留已有挂载、数据库连接、凭据和数据；不要删除数据卷。

- **已成功启动并完成数据库转换的 beta1：**正常升级并启动。复用既有 V4 子步骤标记，不重放旧 V3 规则，也不重新添加既有服务器或节点。部分转换失败或手工改过 schema 的 V4 库须保存现场、检查后处理，不能直接在同一库运行 V3。
- **最终 V3：**先成功启动 `v3.9.2` 或 `v3.9.2-beta.20`，完成其自身转换，备份后再正常启动 V4。更旧或未完成转换的 V3 库会在 schema 写入前被拒绝。
- **V2：**先使用冻结 V3 的历史工具导入并成功启动最终 V3，不能直接导入 V4。
- **新装：**正常初始化。

**V3→V4 不运行 `psp migrate`。** beta2 删除 V2→V3 专用工具，集中必要的 V3→V4 状态、凭据和旧索引桥接；继续保留仍必要的 Ownership/shared-client 上游收敛。已发布 beta1 标签、镜像及历史说明不变。

迁移并非覆盖所有 DDL 的全库事务。自定义索引/约束若依赖退休列，数据库自身删列行为可能修改或删除它们；自定义 schema 须先检查并在备份副本试迁移。回退到 V3 时，必须先停 PSP，再恢复升级前匹配的数据库、配置/环境与原密钥，不能只换旧镜像继续使用已被 V4 修改的数据库。详情见 [V4 升级指南](../UPGRADE-v4.md)。

## 验证边界

本地前端测试、Go 测试/vet、相关 race 检查及构建通过；本地浏览器的安装向导验证使用模拟接口。完整跨数据库、发布目标编译及 Linux 浏览器 smoke 由 PR CI 验证。

**生成材料不等于实机安装验收。** Docker 与 Windows 手动安装尚未做实机端到端验收，SHA-256 校验也不是独立数字签名。升级后仍需检查实际部署的登录、订阅、流量基线、代理连接、同步任务及 Node 状态。

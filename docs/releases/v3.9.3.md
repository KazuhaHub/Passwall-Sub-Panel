
## V3 stable maintenance release

V3 now lives on the independent `release/v3` maintenance branch. This release
keeps the V3 database model and does not include the V4 native-node backend or
V4 migrations.

The compatibility manifest follows the code. Panels now read
`docs/compat/v3.json` from `release/v3` instead of from `main`, so the file a
V3 panel fetches is the file this branch ships and its drift guard checks.
`main` is the V4 line and shares no history with V3; the V3 manifest existed
there only as a hand-copied duplicate, and a missed copy would have stopped
compat refreshes on every deployed V3 panel without any visible failure. That
copy stays in place as a frozen mirror for v3.9.2 and earlier, which have the
old URL compiled in. Upgrading to v3.9.3 needs no action and nothing about the
refresh itself changes: same reactive trigger, same throttle, same fallback to
the on-disk cache when a fetch fails. Only the branch it reads is different.

Upstream compatibility is refreshed for 3X-UI 3.8.5 and S-UI 1.6.3. For
3X-UI's Xray 26.9.9, Mihomo REALITY subscriptions opt in to the required
X25519MLKEM768 key share and use the audited Chrome fingerprint. Known-dead
sing-box REALITY outbounds are omitted instead of being published as working
nodes. Inbound edits also preserve the negative subscription ranks accepted by
3X-UI 3.8.x. S-UI 1.6.3 needs no adapter change; its existing `/apiv2` contract
was reverified through PSP's live adapter suite.

The transitive gRPC dependency is updated to 1.83.2, fixing GO-2026-6348's
HTTP/2 DATA-frame fragmentation memory-exhaustion issue. The release gate now
reports no reachable Go vulnerabilities.

Back up the database and configuration, including encryption/signing keys and
custom rule sets/templates/locales, before upgrading. For SQLite, stop PSP before
copying its database; for MySQL/PostgreSQL use a consistent backup. Do not replace
your existing configuration or data directories with files from the archive.

`ghcr.io/kazuhahub/passwall-sub-panel:v3.9.3` identifies this release. The
rolling `:latest` and `:v3` tags follow stable V3 maintenance releases. The
`:beta` tag remains on the V4 testing line.

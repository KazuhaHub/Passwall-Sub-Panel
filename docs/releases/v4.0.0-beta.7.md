# PSP v4.0.0-beta.7

## 配置确认状态修复

- 修复 Passwall Node 已应用配置后，节点仍显示“配置推送等待重试”。PSP 收到当前配置的有效完整回执后，会清除待同步状态并更新实际端点。
- 保留完整回执校验，并在数据库事务内再次核对服务器绑定及完整监听意图。旧配置、失败或不完整回执不能误清管理员的新修改；存储失败会保留待同步状态并允许重试。
- 同时刷新已缓存的节点列表和订阅输出，下一次订阅读取即可使用已确认配置。重复回执不会反复清缓存。

## 升级与兼容性

本次仅更新 PSP，不发布 Passwall Node 新版本，不更改节点协议、已安装内核或数据库 schema。
无需重装、重新添加服务器或重新配置节点；原配置、凭据、捕获时间、健康及历史流量均保留。
升级后，已有待同步状态会在下一次有效完整配置回执到达时自动收敛；若节点确实未应用配置，
则仍保留待同步提示。端口可达性与真实客户端连接是独立检查，不因配置确认而被强制标为成功。

本版为 Pre-release。Docker 精确标签为
`ghcr.io/kazuhahub/passwall-sub-panel:v4.0.0-beta.7`；`beta` 跟随最新发行，`latest` 仍只指正式版。
升级前请备份数据库和配置。发行本身不会修改线上部署或自动重装节点。

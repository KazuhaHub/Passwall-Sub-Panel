# PSP v4.0.0-beta.4

这是 V4 测试版，新增保留原服务器记录的 3X-UI → Passwall Node 迁移，并统一安装入口。Passwall Node 继续使用已发布、登记兼容的 `v0.0.1-beta3`；本次不发布、自动安装或自动升级节点程序。

## 统一安装入口

管理员在服务器菜单选择“安装 Passwall Node”：已有 Passwall Node 直接读取原身份和固定凭据，3X-UI 先打开只读迁移预检。Linux 二进制 + systemd、Docker 和手动安装方式保留，不另建一套重装流程。

普通 Passwall Node 重装无需停止 PSP，也不执行迁移命令；必须先停止旧节点实例，保留匹配的身份、凭据和数据。安装器的既有覆盖检查仍生效，不支持以重装隐式强制修复残缺安装或替代远程升级。重新打开窗口不会创建服务器或轮换凭据。

## 3X-UI → Passwall Node

迁移保留原服务器、节点、客户端及挂载 ID、受管连接配置和确认过的代理凭据、分组、排序及历史流量，不需要重新添加服务器或重建受管节点。新 Agent 身份和加密固定安装凭据绑定到原服务器记录；原 3X-UI 不会自动卸载。

**安装入口提供预检，不是在线一键转换。** 使用短维护窗口：

1. 预检所有阻断和警告，选择核验过的准确 Xray 版本；已知当前版本优先，切换推荐版本须显式选择。
2. 备份完整数据库、配置/环境及原加密密钥，保留旧节点配置和证书文件。
3. 完全停止所有共用数据库的 PSP 实例，停止节点机上的旧 Xray 并防止自动重启。
4. 通过同一 PSP 镜像/二进制运行 `psp migrate-server`，默认 dry run；确认指纹、准确版本和三项维护条件后才执行 `--apply`。
5. 转换成功后重启 PSP，在同一原服务器选择“安装 Passwall Node”，安装节点程序并等待实际配置、客户端及内核状态收敛，再测试代理连接。

完整命令和注意事项见 [服务器迁移指南](../server-migration.md)。不要在仍运行的 PSP 容器中用 `docker exec` 执行转换；命令结果未确认时先检查原记录，不要盲目恢复旧 Xray。

## 迁移边界

- 本次仅开放可核验的 PSP-managed Xray VLESS、VMess、Trojan 和 Shadowsocks。未捕获/未确认配置、凭据轮换冲突、跨服务器或孤立挂载、非零 inbound 到期时间及外部文件依赖会阻断。
- 手工客户端/入站、全局路由、DNS、出站和外部证书文件不导入。依赖 WARP、自定义出站或本地 fallback 的节点必须先处理依赖，不能只确认 `--managed-only` 就继续。
- REALITY 与非空 `finalmask.tcp` 组合会阻断；需要先在原节点清理、重新抓取并确认配置，不静默删字段。
- 连接/IP/设备限制差异作为警告报告，不能假定新旧后端完全等价。
- 原服务器的旧节点动作任务保留为不可重试的 `retired` 状态；不清理其他服务器或普通用户、邮件、证书任务。界面的“重建 inbound”是另一项功能，本次没有删除。
- 历史流量不清零，新节点计数 epoch 建立新的原始基线；旧 Xray 停止前未被轮询的字节无法重建。
- **S-UI 迁移尚未开放。** 现有快照不能证明原始 sing-box 的 transport/TLS 字段完整，需要原始配置比对及真实内核版本核验。

## 升级与验证

从已正常启动的 V4 升级，仅替换 PSP 镜像/二进制并保留原数据库、配置/环境、加密密钥和数据卷；升级本身不转换服务器后端。V3/V2 的升级与回退限制继续遵循 [V4 升级指南](../UPGRADE-v4.md)，不要删除数据卷或只更换旧镜像读取已转换数据库。

本地完整 Go 测试/vet、295 项前端测试及生产构建通过；迁移事务、失败注入、固定凭据复用与已发布 Node 的同步契约已有回归覆盖。跨数据库、Linux 浏览器 smoke、六平台编译及容器发布由 CI 验证。真实 Node 契约测试使用确定性的无代理内核运行时，不代表新一次真实握手或生产部署验收；迁移完成后仍须检查实际登录、订阅、流量和代理连接。

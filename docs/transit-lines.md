# 托管中转：PN 服务器之间的中转线路

> 状态：第 1 期（透传）已实现于开发分支（2026-11-16）。只针对 Passwall Node（`PanelKind = psp`）作为入口。

## 1. 目标

`用户 → A → B → 目标`，A 是 PN 服务器，转发由 PSP 下发和管理。一台服务器可以只做中转、只做落地或两者都做，**不设角色字段**，由线路的引用关系推出来。

## 2. 模型：中转线路的“入口”

沿用现有的中转线路（`domain.RelayLine`），新增一个属性 `EntryPanelID`：

| 入口 | 谁配转发 | 行为 |
|---|---|---|
| 外部（`0`，旧数据的默认值） | 管理员在面板外配（realm/gost/iptables、CDN） | 与以前完全相同 |
| PN 服务器（非 `0`） | PSP 下发给该服务器 | 中转服务器确认生效后才发布 |

这和同行的模型一致：V2Board/Xboard 把中转当成落地节点的子节点，只是转发要手动配。我们把同一个概念的“转发”这一步交给 PN。线路的其他能力原样可用，不用另写：订阅生成、线路 Region/Tags、分组可见性、“按线路选择”、健康探测。

线路本身仍存在 `nodes.relays`（管理员拥有）。托管才需要的运行状态单独放在 `transit_forwards` 表里，每条托管线路一行，只由同步服务写：

- 下发给节点的转发键 `fwd_<id>`；
- 中转服务器最近确认的转发（入口、端口、目标、目标端口）；
- 转发流量。

这样同步服务永远不改写管理员的列，两台中转服务器同时确认同一落地的不同线路也不会互相覆盖。

## 3. 两种方式

| | 透传（第 1 期，已实现） | 隧道（第 2 期，已实现） |
|---|---|---|
| 链路 | A 原样转发到 B 的用户入站 | A 解开用户协议，经 A—B 隧道从 B 出口 |
| 身份、计费、审计在 | B | A（按 B 的规则，见 §5） |
| A 持有用户凭据 | 否 | 是 |
| 隧道协议 | 无 | 每条链路可选：SS-2022（不过墙）／VLESS+REALITY（过墙） |

## 4. 场景

| A 的位置 | A→B | 推荐 |
|---|---|---|
| 境外 | 境外互通 | A 可信时用隧道（SS-2022），否则用透传 |
| 境内 | 专线 | 透传 |
| 境内 | 公网过墙 | 透传（B 自己的协议负责抗封锁）；要用隧道必须选 VLESS+REALITY |

入口端口由管理员填写，适配只开放部分端口的 NAT 机。

## 5. 访问策略跟着出口走

一条连接适用它出口服务器的规则。

- B 禁止 X：直连 B、经 A 透传、经 A 隧道，都禁止。
- A 禁止 X，B 不禁止：直连 A 禁止；经 A 到 B 的连接不禁止。

透传时执法本来就在 B。节点上，转发的流量**不进入**中转服务器自己的策略路由：路由的第一条规则就把转发直接交给 `direct`。否则落地是专线内网地址时，会被中转服务器上的“禁止私网”规则拦下。真实内核测试和变异测试覆盖了这一点。

隧道时执法在 A：A 编译策略时，按服务器划定范围的规则对走隧道的入站改看出口服务器，并用 `DestinationRule.Inbounds` 限定入站，不需要改协议。例如范围只含 A 的规则不再作用于从 B 出口的入站，范围只含 B 的规则只作用于它们；范围同时含 A、B 的规则照旧作用于全部入站。没有隧道的服务器，策略和编译缓存键都与以前相同。B 上隧道的入站同样直接交给 `direct`，不再经过 B 的策略。

## 6. 第 1 期实现

**Protocol**
- 能力 `transit.forward.v1`。
- `ConfigBody.Transit.Forwards`：`omitempty`，没有线路时配置字节不变。
- `ForwardKey`（`fwd_<id>`）是独立类型，不会被解析成监听器键。
- 转发作为 config 流对象上报四态；`ForwardCounters` 只出现在全量报告。

**Node**
- Xray 编译为 `dokodemo-door`，sing-box 编译为带 override 的 `direct` 入站。
- 与监听器同端口时，只拒绝该转发对象本身。
- Xray 统计转发流量；sing-box 本期只跳过转发连接、不计量（第 3 期起 sing-box 也计量，见第 7 节「第 3 期补充」）。

**PSP**
- 只向声明了能力的中转服务器下发。
- 端口已被该服务器自己的入站占用、或两条线路争同一端口时，在下发前就撤下，不让节点因此拒绝整份配置。
- 中转服务器持有当前配置并报告 `applied` 时记为确认，`rejected` 等其他状态撤销确认。
- 线路的 `Publishable()` 要求确认内容与当前期望完全一致：改端口、改落地地址或端口后，旧的确认不再算数。读取不到状态时同样不发布，即“失败即关闭”。
- 流量只接受发给该中转服务器的转发键，并按计数器 epoch 处理重置。转发流量不计入任何用户。

**保存时校验**
- 入口必须是 PN 服务器，且不是落地自己所在的服务器。
- 必须填写入口端口，不能覆盖 SNI 或 Host。
- 入口端口不能与该服务器的入站或其他托管线路冲突，停用的入站和线路也算。

## 7. 第 2 期实现

**模型**：节点增加“出口服务器”（`egress_panel_id`，0 为本服务器）。每对有序服务器（入口 A，出口 B）一条隧道，A 上所有出口为 B 的节点共用。

**Protocol**
- 能力 `transit.link.v1`。
- `Transit.LinksIn`（出口持有）、`LinksOut`（入口持有）、`Egress`（入站 → 隧道），都是 `omitempty`。
- `LinkKey`（`lnk_<id>`）独立类型；隧道作为 config 流对象上报四态；`LinkCounters` 只出现在全量报告。
- 隧道协议：`ss2022`（2022-blake3-aes-128/256-gcm）或 `vless_reality`（指纹 chrome 等）。

**Node**
- 出口：SS-2022 或 VLESS+REALITY 入站，直接交给 `direct`。REALITY 走与普通入站相同的客户端兼容检查。
- 入口：每条隧道一个出站。允许类规则按出口拆分：本机组保留原规则，每条隧道组得到一份副本（规则标签加 `~lnk_N` 后缀）指向隧道出站；拦截规则不拆分（第 3 期带 `AuditEgress` 时例外，见「第 3 期补充」）；每个隧道组最后有兜底规则。隧道断开时连接失败，不回退从 A 直出。
- 审计按 `~` 前去掉后缀找回原规则。
- 计数：隧道的出入口各自计数；Xray 提供，sing-box 在第 3 期补上（见下面的「第 3 期补充」）。
- 真实内核矩阵（入口 × 出口内核 × 协议，共 8 种）覆盖 TCP、UDP、入口拦截规则，以及出口停止后不回退。

**PSP**
- 隧道在第一次需要时创建，同时生成两种协议的全部凭据（SS 密钥、X25519 密钥对、UUID、short id），切换协议无需新凭据。REALITY 伪装站点从默认列表随机选取，管理员可以修改。
- 出口端口在 20000–59999 中随机分配，避开出口服务器的入站、进入它的托管线路和其他隧道。
- 入口拨号的地址：管理员填写的出口地址；留空时用 PSP 最近一次看到出口服务器同步的来源地址。新建节点时连接地址同样默认取服务器地址，可修改。
- 只向声明了 `transit.link.v1` 的服务器下发。出口端口被入站占用、或没有可用地址时，在下发前撤下该半边。
- 两侧各自记录“已下发”和“已确认”的摘要；入口一侧的摘要包含绑定的入站。节点只在两侧都确认当前内容、且该节点在入口已下发的绑定里时才发布（`EgressReady`），否则从订阅中撤下，不回退直出。
- 隧道流量取入口的计数，入口没有时取出口的；不计入任何用户。

**保存时校验**
- 节点和出口都必须是 PN 服务器，且出口不是节点自己的服务器。
- 隧道设置：协议必须是两者之一；出口地址必须是合法主机；REALITY 伪装站点必须合法。

### 第 3 期补充：命中记录出口与 sing-box 计量

- **sing-box 计量**：sing-box 服务器也统计转发与隧道的流量（转发、隧道的入口与出口各自计数），按计数器 epoch 处理重置；没有 Xray 时的“只跳过、不计量”不再成立。
- **命中记录出口**：PSP 只在四个条件同时成立时给策略置 `AuditEgress`——该 agent 声明了能力 `audit.hits.egress.v1`、编译引擎是 Xray、该服务器有出口绑定（编译输入的 `Egress` 非空）、记录没有关闭（协议校验拒绝“记录关闭却带出口标志”）。没有隧道的服务器和 sing-box 服务器收到的策略与摘要和以前逐字节相同；能力进入编译缓存键，能力变化会重新编译；回退到最近已知良好策略时标志只降不升。策略带该标志时：策略带 `AuditEgress` 标志时，入口给每条命中附上它经过的隧道（`AuditHit.Egress`，空表示从本服务器直出）。标志只在 Xray 上生效；拦截规则也只在这个标志下按隧道拆分（每条隧道一份副本），不带标志时拦截规则不拆分，与以前字节相同。
- 入库（`destaudit`）按链路号一次查出 `{入口, 出口}`：链路不存在、入口不是上报的服务器、或 agent 没声明 `audit.hits.egress.v1` 却带了出口，这条命中丢弃并计入丢弃类型 `egress_unknown`（指标 `hits_egress_unknown`，计入命中记录的 `dropped_in_range`）；查询失败按其他数据库错误处理，整批作废。链路从不删除、入口出口永不改变，所以结果可信。
- `dest_hits` 增加 `egress_panel_id`（0 = 从本服务器直出，也是已有行的值），列入主键，并有索引 `(egress_panel_id, hour_ms)`。升级时由 4.2 迁移重建表（见 `schema_upgrade_v4_2.go`）。管理接口 `GET /dest/hits` 接受 `exit_panel_id`（0 合法，不带表示不筛选）和 `group_by=exit`。`exit_panel_id` 只出现在未分组的行和 `group_by=exit` 的行上，`site`、`user`、`policy` 分组的行不带它（0 会被误读成“直出”）。

## 8. 规则（不变量）

1. 用户流量只在身份终结的那一跳计配额，另一跳记为链路流量。
2. 托管线路只在中转服务器确认当前转发后发布；隧道节点只在两侧都确认当前隧道后发布。失效时撤下，不回退直连或直出。
3. 转发和隧道入站不进入策略路由，只去固定去向。
4. 没有托管线路和隧道的服务器，配置字节、策略和编译产物与以前相同。

## 9. 来源 IP

透传时 B 只看到 A，基于 IP 的限制对经此线路的连接不生效，界面已标明。

**保留来源推迟到后续阶段（原定第 3 期）。** 现在基于 IP 的限制只观察、不执行（`IPShadow`），保留来源也不会让任何限制真正生效，所以先不做。

可选的“保留来源”（后续阶段）：仅两端都是 Xray 时可用，默认关闭，B 为该线路单独开影子端口接收 PROXY 头。依据是以下实测结论：

- sing-box 已移除 PROXY 协议，而且 `check` 能通过、启动才失败；
- 开启后同一端口上的直连会断；
- PROXY 头可被持有凭据的人伪造。

## 10. 多跳（预留）

`境内入口 → 境外中转 → 落地` 暂不支持，第 2 期的隧道结构为它预留位置，启用时需要成环检测和跳数上限。

## 11. 分期

1. **透传**（已实现）。
2. **隧道**（已实现）：两种隧道协议，加按出口的策略编译。
3. **审计出口维度 + sing-box 计量**（已实现）：命中记录出口服务器（`AuditEgress`，仅 Xray）；sing-box 转发与隧道也计量。
4. 透传保留来源（原第 3 期，推迟：IP 限制目前只观察、不执行）。
5. 链路质量自测、按目标分流、多跳、按线路设流量倍率。

发布顺序：Protocol 打标签 → Node 换正式依赖并发布 → PSP 换正式依赖。

## 12. 链路质量自测与压缩同步（4.3，开发分支）

**自测（`transit.probe.v1`）**

- 只向声明了该能力、且持有出口链路（`LinksOut`）或转发的服务器下发 `Transit.Probe`；没有声明的 agent 收到的配置与以前逐字节相同。
- 设置（管理员，`GET/PUT /api/admin/transit/probe-settings`）：开关（默认开）、间隔（60 秒，30–3600）、超时（5000 毫秒，500–10000）、探测地址（默认 `https://www.gstatic.com/generate_204`，http/https，端口 1–65535；**留空表示只测传输**：不经隧道抓取，不下发 `link_url`，没有 e2e 结果，芯片显示传输的数字）、撤下开关（默认关）、连续失败 N 次撤下（3）、连续正常 N 次恢复（3）。越界一律拒绝，不静默修正。
- 转发探测方法：默认 `tcp`；落地监听是纯 UDP（Hysteria2、TUIC）时用 `quic`；转发是 SNI 共用端口的路由目标时用 `tls`（见第 13 节；协议规定这种转发不能用 `tcp`，决定在 `linkprobe.Method`，由同步服务在发出前套用）。
- 入库只收下发配置里的对象，且只收对的一侧：`LinksOut` 的 `e2e`／`transport`、转发的 `forward`；其余丢弃。状态表 `transit_probe_state`。
- 一个窗口：全部失败（且至少 3 次尝试）为 `down`，失败率不低于 20% 为 `degraded`，其余 `ok`；没有尝试或结果过期（超过 3 个上报间隔，取探测间隔与全量上报周期中较大者）为 `unknown`。
- 撤下：只在撤下开关打开时，连续 N 个 `down` 窗口置位、连续 M 个 `ok` 窗口清除。只数**新**窗口：内容（尝试、失败、RTT、最近成功、最近错误）变了算新窗口；内容不变（一直中断的链路每次都一样）则隔一个探测间隔才算一个。重复上报（同一 agent 时间戳且内容相同）整条忽略，agent 时钟回拨或跳到未来不会卡住状态。结果过期后整段历史作废，从新窗口重新判断；`unknown` 永不撤下并清除标记。关掉探测或撤下开关会立即清除所有撤下标记，读取时也只在开关打开时才认标记。被撤下的托管线路（`RelayLine.Publishable()`）或隧道节点（默认出口的链路，`withoutUnreadyEgress`）从订阅中去掉，永不回退直连。`health.go` 不变。
- 用户页 `relay_statuses` 只带粗略质量（ok／degraded／down）和中位 RTT。

**压缩同步（`sync.gzip.v1`）**

- `/v1/node/sync` 只接受声明过该能力的 agent 的 gzip 请求（其余带 `Content-Encoding` 的请求为 415）；线上 16 MiB、解压后 64 MiB，先读完线上字节（受 16 MiB 限制），再取解压槽，只在解压时占用；解压并发由信号量限制为 4，同一 agent 同时只解一份；等不到槽返回 503（带 `Retry-After`，agent 保持状态、下次轮询重发）。对声明了该能力的 agent，所有响应带 `Vary: Accept-Encoding`。指标：`psp_node_sync_gzip_refused_total`（415）、`psp_node_sync_decode_busy_total`（503）、`psp_node_sync_gzip_bytes_total`。
- 对声明了该能力的 agent，每个 2xx 响应带 `Accept-Encoding: gzip`；请求带 `Accept-Encoding: gzip` 时响应也压缩。没有该能力的 agent 行为不变。

## 13. SNI 共用端口（`transit.sni.v1`，4.3，开发分支）

一个 TCP 端口按 TLS 握手里的 SNI 分给多个用途：Node 读取每个连接的 ClientHello（不解密），把连接交给对应的监听器、中转线路或外部伪装站点。只有 Xray 能做到。

**规则（不变量）**

1. **设置只作用于它所设在的那一项**：共用端口、每个监听器的回环端口、每条路由的 SNI、默认站点，都是管理员保存的值。自动值只是编辑器里的预填（按钮“随机生成”），发送时不会改写任何一项。
2. **任意 TCP 端口都能共用**（默认 443）；一台服务器可以有多个共用端口，最多 16 个（协议上限），每个端口至多一个前置。
3. **只有 Node 能承载的监听器能放在后面**，规则与 Node 的 `frontUnfit` 一致：传输为空／`tcp`／`raw`，安全层为 tls 或 reality，且自己不接收 PROXY 头（`sockopt`、`rawSettings`、`tcpSettings` 的 `acceptProxyProtocol`，因为前置会再写一个）。PSP 比 Node 更严的一点：只接受 VLESS／VMess／Trojan（这些协议的客户端才会发订阅渲染出来的服务器名）；没有服务器名（REALITY 的 `serverNames` 为空、TLS 的 `serverName` 为空）的监听器不能前置，因为没有可匹配的 SNI。监听器 JSON 按精确键名读取（与 Node／Xray 一致），大小写不同的重复键不会让面板比 Node 更宽松。WebSocket／gRPC／XHTTP、SS-2022、Hysteria2、TUIC 等保持自己的端口，保存时拒绝并说明原因。
4. **只发给 Xray，且是真的在跑 Xray**：agent 声明了 `transit.sni.v1`、期望引擎是 Xray、并且本次报告的引擎是 Xray 才下发 `Transit.Fronts`；其他服务器的配置字节与以前相同，界面显示“SNI 共用端口需要 Xray”并禁用，已保存的前置显示为“未生效”并写出原因。声明缺失会让节点把已移到回环端口的监听器丢掉，所以这是必须的门。
5. **没有前置时配置字节不变**：`Fronts` 为 `omitempty`，同步服务在没有任何前置时一字不改（测试逐字节对比整份配置）。
6. **冲突阻止保存并指名**：同一 SNI 在一个前置里出现两次、端口已被监听器／转发／隧道端口／另一个前置或回环端口占用、回环端口落在 Node 内部探测范围 `127.0.0.1:31000-31999` 或 Node 自留的 `127.0.0.1:10085`（核心 API），保存被拒绝，信息里写出冲突的那个对象。端口占用视图也列出这些。
7. **路由名必须是客户端真会发的名字**：去往监听器的路由，名称必须是该监听器自己的 REALITY `serverNames`／TLS `serverName`，并且到它的路由合起来必须**包含订阅给它的客户端的那个名字**（REALITY 的第一个 `serverNames`，按写入顺序；TLS 的 `serverName`），其余名字可以多；去往中转线路的路由同理：名称是落地节点的 SNI（托管线路本来就不能覆盖 SNI，订阅里渲染的就是落地的第一个名称），必须包含它，且落地必须是 TCP 上的 TLS／REALITY 监听器，UDP 或无 TLS 的落地不能走共用端口，也绝不会被静默改成只 TCP。节点保存也受此约束：改掉被路由引用的名称（包括调换第一个名称使订阅渲染的名字不在路由里）、传输、协议，会被拒绝并指出前置和路由。
8. **默认去向是外部站点**（`FrontTarget.External`）：选定、随机生成或手填。PSP 拒绝等于本服务器自己公网地址（或解析到它）且端口等于前置端口的默认站点，因为连接会绕回前置；手填的名称与服务器自己的任一地址（观察到的地址、节点地址）逐字相同（不分大小写、忽略结尾的点）也拒绝，即使 DNS 解析失败。保存时的 DNS 并行解析，总预算 3 秒。
9. **会移动或停用东西的改动，是需要确认的单独动作**（409 `confirm_required`，写出受影响的对象）：把已占用该端口的监听器放到前置后面（用户重连一次）；监听器在节点保存时落到共用端口上（响应写出前置、它将用的 SNI 和回环端口，确认后在同一次保存里加入前置并审计 `transit_front_listener_joined`，绝不静默）；**监听器离开前置**——把前置后面的监听器改到别的端口，或删除它：先确认，确认后同一次操作把它和它的路由从前置里去掉（审计 `transit_front_listener_left`；前置后面只剩它时拒绝，请先删前置）；停用共用端口后面的监听器（它的 SNI 改去默认站点，允许，但先确认）；删除前置、改端口、去掉中转线路路由；把服务器的引擎切离 Xray（前置保留但不再下发）。在前置编辑器里直接去掉一个仍监听共用端口的监听器会被拒绝，请先改它自己的端口。
10. **前置不发时，后面的监听器不能撞同一个端口**：Node 不允许两个监听器绑同一个端口，整份配置会被拒绝。所以删除前置、改前置端口、把服务器切离 Xray——只要有两个及以上监听器共用这个端口——是**拒绝**而不是确认，信息点名这些监听器，要先把它们分别改到不同端口；只剩一个监听器时才允许（它回到自己的公网端口）。同步时对称处理（与 Node 的 `WithoutFront` 一致）：一个没有发出的前置（被撤下、没有能力、不是 Xray、协议拒绝……），如果它的监听器加上端口上其他启用的监听器多于一个，这些监听器这次就不下发，并为每个记一条问题（`front_withheld`，详情 `listener_unserved`，写明与谁同端口）；只有一个时回退到公网端口。被省掉的监听器同时不进名册，没有悬空引用。
11. **删除服务器会同时删除它的前置**（逐条审计）；孤儿前置（服务器已不存在）不再阻止任何中转线路或节点的编辑。
12. **同一台服务器上读后写的保存串行化**（按服务器 ID 的互斥锁，前置保存和会碰前置的节点保存共用一个服务实例），回环端口不会被并发保存分配两次。

**数据模型**

表 `transit_fronts`（`ID`、`PanelID`、`Port`、`Spec` JSON、时间戳），`(panel_id, port)` 唯一；前置的线上键是 `fnt_<id>`。`Spec` 是 `domain.FrontSpec`：

- `Listeners`：`{node_id, loopback_port}`——监听器保留它公网端口的配置，节点把它绑到 `127.0.0.1:loopback_port`；
- `Routes`：`{server_names, target}`，名称小写、精确匹配、排序；目标是 `listener`（`node_id`）或 `forward`（落地节点 `node_id` + 中转线路 `line_id`）；
- `Default`：`external`（`host`、`port`）。

升级：只多一张表，由 `autoMigrateCurrentSchema` 创建，没有数据要搬，所以 `schema_upgrade_v4_3.go` 里只记了一条说明；升级测试在 `transit_front_repo_test.go`（SQLite／MySQL／PostgreSQL 都跑）。

**编译（`service/front`）与下发**

- `PlanFor` 在 agent 没有能力或引擎不是 Xray 时返回空计划。否则把每个前置编成 `nodeprotocol.Front`：路由按首个名称排序，目标是中转线路的，用该线路的转发（`transit_forwards` 行 id）并把它的网络改成只 TCP。
- 不可达的目标（落地停用、线路已不在这个端口）只丢掉那条路由，不影响其余；监听器不在这台服务器的配置里、或没有路由再指向它，就把它留在公网端口；一个前置没有任何路由，整个不发。
- 同步服务把共用端口和回环端口当作已占用：不属于前置的转发或隧道在这些端口上照旧被撤下；属于前置的转发在前置端口上发出。最后整体过一遍 `ValidateTransit`，被协议拒绝就撤下全部前置和它们的转发（监听器留在公网端口），并记录日志。
- 前置后面的转发用 `tls` 探测（协议拒绝对它用 `tcp`）。
- 被停用的监听器不作为前置监听器下发（Node 会拒绝点名未服务监听器的前置），指向它的路由一并去掉，其余监听器照常；端口上有启用的监听器不在前置后面、或前置后面的监听器已不能被承载时，整个前置不发（否则 Node 拒绝整份配置）。
- 每个前置各自过协议校验（单独、再放进除前置外的其余配置里），所以只撤下有错的那个，别的对象（如隧道）的错误不会连累前置；通过的几个再一起校验一次，互相冲突才全部撤下；撤下前置时，为该服务器记一条问题 `front_withheld`（键为 `fnt_<id>`，详情写原因，出现在“节点问题”里），计数 `psp_fronts_withheld_total{reason}`，共用端口对话框和服务器行都会显示“未生效”。
- 保存时的协议校验是干跑，不写任何行（不为转发生成行 ID）。

**保存时校验（`service/front`、`service/node`）**

- 前置：服务器是 Node、引擎 Xray、已声明能力；端口 1–65535 且不在 Node 内部探测范围 `127.0.0.1:31000-31999`；监听器可前置、监听在这个端口、回环端口不与任何已用端口相同；每个被移动的监听器至少有一条路由；路由目标是已选的监听器，或在这个端口入口的托管中转线路；默认站点是外部站点；最后用协议的校验兜底。链路隧道出口作为目标**预留了接口位**（`FrontTargetLink`，保存时明确拒绝），见“未做”。
- 节点保存：被前置使用的监听器不能改端口、不能改成 Node 承载不了的传输或协议、不能丢掉被路由引用的名称、不能删除；落在共用端口上的监听器会被提议加入前置（见规则 9）；也不能占用某个前置的回环端口；被路由引用的中转线路不能改端口、改入口或删除；中转线路可以进入共用端口（多条线路共享一个端口，靠 SNI 区分）。

**接口（adminGroup）**

`GET/POST /servers/:id/fronts`（GET 同时给出 `support`、`withheld`）、`PUT/DELETE /servers/:id/fronts/:fid`（`DELETE ?confirm=true`）、`GET /servers/:id/fronts/options`（候选监听器及不能前置的原因、候选中转线路）、`GET /servers/:id/fronts/suggest?what=loopback|camouflage`（只读的预填）、`GET /servers/:id/ports`（端口占用）。拒绝返回 `code` 和 `params`，界面按 `code` 写自己的文案。写入审计为 `transit_front_created／updated／deleted`（带前后内容），外加通用的请求审计。

**端口占用视图**（服务器页的“共用端口（SNI）”→“端口占用”）：只读，列出这台服务器用到的每个端口——监听器、中转线路（未被路由选中的标出）、隧道端口、每个共用端口及其后面的 `SNI → 去向` 与默认站点、前置的回环端口、Node 内部探测范围 `127.0.0.1:31000-31999`。

**界面说明（ⓘ）**：什么是 SNI 共用、客户端不能把 ClientHello 拆到多个 TLS 记录里、纯 HTTP 探测要等约 1 秒才到默认站点、监听器会被移到回环端口且用户重连一次。

**其他保存路径**：新建时不会把会加入前置的创建放进重试队列（失败就返回错误，由管理员重试，否则排队的创建会在没有加入的情况下落在共用端口上）；加入前置时不再对已保存的默认站点做第二次 DNS 校验；加入失败（竞态或故障）时节点已保存，同步会按上面的规则撤下会撞端口的监听器并记问题。同一台服务器的锁在新建、导入、编辑、停用、删除、分离时都先于任何读取取得，键按升序取，不会交叉死锁。

**监听器在两个共用端口之间换位**（A 的端口改到 B 的端口）：一次确认同时写出离开 A（路由改去 A 的默认站点）和加入 B（SNI、回环端口），确认后同一次保存里先离开再加入，两条都审计；任一步成功后即使后面失败也会写审计。只缩小前置的操作（监听器离开、删除或分离节点、只删路由的编辑、删除前置）不受“服务器必须能跑前置”的门限制，所以服务器切到 sing-box 或丢了能力之后，有多个监听器的前置仍能被清空；任何新增或改动仍需要门。启用前置后面的一个已停用监听器，而该前置没有下发、端口上还有别的启用监听器时，先 409 确认（它们都会保持停止，写出前置未下发的原因）。

**已接受的限制**：加入／离开和节点保存不在同一个事务里，中途失败靠同步时的安全网（撤下会撞端口的监听器并记问题）兜底；排队执行的旧式创建和采纳（Adopt）同样靠这个安全网；被撤下的监听器仍会出现在订阅里（订阅渲染不看下发状态），由可见的问题提示。

**未做／已知限制**

- 隧道出口（`Link`）作为前置目标：协议和模型都留了位，但隧道的端口和 REALITY 服务名目前由 `service/transit/link.go` 自行分配，要让它跟着路由走需要单独的改动，所以现在保存时拒绝。
- 前置自身的收敛状态（`fnt_<id>` 的 config 对象）暂不存、不在界面显示；其目标转发的确认照旧决定线路是否发布。
- 默认站点的域名只在保存时解析一次；以后它改成解析到本机，不会重新检查。

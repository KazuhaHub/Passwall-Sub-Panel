# 托管中转：PN 服务器之间的中转线路

> 状态：第 1 期（透传）已实现于开发分支（2026-11-16）。只针对 Passwall Node（`PanelKind = psp`）作为入口。

## 1. 目标

`用户 → A → B → 目标`，A 是 PN 服务器，转发由 PSP 下发和管理。一台服务器可以只做中转、只做落地或两者都做，**不设角色字段**，由线路的引用关系推出来。

## 2. 模型：中转线路的“入口”

沿用现有的中转线路（`domain.RelayLine`），新增一个属性 `EntryPanelID`：

| 入口 | 谁配转发 | 行为 |
|---|---|---|
| 外部（`0`，旧数据的默认值） | 管理员在面板外配（realm/gost/iptables、CDN） | 与以前完全相同 |
| PN 服务器（非 `0`） | PSP 下发给该服务器 | 中转服务器确认生效后才发布 |

这和同行的模型一致：V2Board/Xboard 把中转当成落地节点的子节点，只是转发要手动配。我们把同一个概念的“转发”这一步交给 PN。线路的其他能力原样可用，不用另写：订阅生成、线路 Region/Tags、分组可见性、“按线路选择”、健康探测。

线路本身仍存在 `nodes.relays`（管理员拥有）。托管才需要的运行状态单独放在 `transit_forwards` 表里，每条托管线路一行，只由同步服务写：

- 下发给节点的转发键 `fwd_<id>`；
- 中转服务器最近确认的转发（入口、端口、目标、目标端口）；
- 转发流量。

这样同步服务永远不改写管理员的列，两台中转服务器同时确认同一落地的不同线路也不会互相覆盖。

## 3. 两种方式

| | 透传（第 1 期，已实现） | 隧道（第 2 期，已实现） |
|---|---|---|
| 链路 | A 原样转发到 B 的用户入站 | A 解开用户协议，经 A—B 隧道从 B 出口 |
| 身份、计费、审计在 | B | A（按 B 的规则，见 §5） |
| A 持有用户凭据 | 否 | 是 |
| 隧道协议 | 无 | 每条链路可选：SS-2022（不过墙）／VLESS+REALITY（过墙） |

## 4. 场景

| A 的位置 | A→B | 推荐 |
|---|---|---|
| 境外 | 境外互通 | A 可信时用隧道（SS-2022），否则用透传 |
| 境内 | 专线 | 透传 |
| 境内 | 公网过墙 | 透传（B 自己的协议负责抗封锁）；要用隧道必须选 VLESS+REALITY |

入口端口由管理员填写，适配只开放部分端口的 NAT 机。

## 5. 访问策略跟着出口走

一条连接适用它出口服务器的规则。

- B 禁止 X：直连 B、经 A 透传、经 A 隧道，都禁止。
- A 禁止 X，B 不禁止：直连 A 禁止；经 A 到 B 的连接不禁止。

透传时执法本来就在 B。节点上，转发的流量**不进入**中转服务器自己的策略路由：路由的第一条规则就把转发直接交给 `direct`。否则落地是专线内网地址时，会被中转服务器上的“禁止私网”规则拦下。真实内核测试和变异测试覆盖了这一点。

隧道时执法在 A：A 编译策略时，按服务器划定范围的规则对走隧道的入站改看出口服务器，并用 `DestinationRule.Inbounds` 限定入站，不需要改协议。例如范围只含 A 的规则不再作用于从 B 出口的入站，范围只含 B 的规则只作用于它们；范围同时含 A、B 的规则照旧作用于全部入站。没有隧道的服务器，策略和编译缓存键都与以前相同。B 上隧道的入站同样直接交给 `direct`，不再经过 B 的策略。

## 6. 第 1 期实现

**Protocol**
- 能力 `transit.forward.v1`。
- `ConfigBody.Transit.Forwards`：`omitempty`，没有线路时配置字节不变。
- `ForwardKey`（`fwd_<id>`）是独立类型，不会被解析成监听器键。
- 转发作为 config 流对象上报四态；`ForwardCounters` 只出现在全量报告。

**Node**
- Xray 编译为 `dokodemo-door`，sing-box 编译为带 override 的 `direct` 入站。
- 与监听器同端口时，只拒绝该转发对象本身。
- Xray 统计转发流量；sing-box 本期只跳过转发连接、不计量（第 3 期起 sing-box 也计量，见第 7 节「第 3 期补充」）。

**PSP**
- 只向声明了能力的中转服务器下发。
- 端口已被该服务器自己的入站占用、或两条线路争同一端口时，在下发前就撤下，不让节点因此拒绝整份配置。
- 中转服务器持有当前配置并报告 `applied` 时记为确认，`rejected` 等其他状态撤销确认。
- 线路的 `Publishable()` 要求确认内容与当前期望完全一致：改端口、改落地地址或端口后，旧的确认不再算数。读取不到状态时同样不发布，即“失败即关闭”。
- 流量只接受发给该中转服务器的转发键，并按计数器 epoch 处理重置。转发流量不计入任何用户。

**保存时校验**
- 入口必须是 PN 服务器，且不是落地自己所在的服务器。
- 必须填写入口端口，不能覆盖 SNI 或 Host。
- 入口端口不能与该服务器的入站或其他托管线路冲突，停用的入站和线路也算。

## 7. 第 2 期实现

**模型**：节点增加“出口服务器”（`egress_panel_id`，0 为本服务器）。每对有序服务器（入口 A，出口 B）一条隧道，A 上所有出口为 B 的节点共用。

**Protocol**
- 能力 `transit.link.v1`。
- `Transit.LinksIn`（出口持有）、`LinksOut`（入口持有）、`Egress`（入站 → 隧道），都是 `omitempty`。
- `LinkKey`（`lnk_<id>`）独立类型；隧道作为 config 流对象上报四态；`LinkCounters` 只出现在全量报告。
- 隧道协议：`ss2022`（2022-blake3-aes-128/256-gcm）或 `vless_reality`（指纹 chrome 等）。

**Node**
- 出口：SS-2022 或 VLESS+REALITY 入站，直接交给 `direct`。REALITY 走与普通入站相同的客户端兼容检查。
- 入口：每条隧道一个出站。允许类规则按出口拆分：本机组保留原规则，每条隧道组得到一份副本（规则标签加 `~lnk_N` 后缀）指向隧道出站；拦截规则不拆分（第 3 期带 `AuditEgress` 时例外，见「第 3 期补充」）；每个隧道组最后有兜底规则。隧道断开时连接失败，不回退从 A 直出。
- 审计按 `~` 前去掉后缀找回原规则。
- 计数：隧道的出入口各自计数；Xray 提供，sing-box 在第 3 期补上（见下面的「第 3 期补充」）。
- 真实内核矩阵（入口 × 出口内核 × 协议，共 8 种）覆盖 TCP、UDP、入口拦截规则，以及出口停止后不回退。

**PSP**
- 隧道在第一次需要时创建，同时生成两种协议的全部凭据（SS 密钥、X25519 密钥对、UUID、short id），切换协议无需新凭据。REALITY 伪装站点从默认列表随机选取，管理员可以修改。
- 出口端口在 20000–59999 中随机分配，避开出口服务器的入站、进入它的托管线路和其他隧道。
- 入口拨号的地址：管理员填写的出口地址；留空时用 PSP 最近一次看到出口服务器同步的来源地址。新建节点时连接地址同样默认取服务器地址，可修改。
- 只向声明了 `transit.link.v1` 的服务器下发。出口端口被入站占用、或没有可用地址时，在下发前撤下该半边。
- 两侧各自记录“已下发”和“已确认”的摘要；入口一侧的摘要包含绑定的入站。节点只在两侧都确认当前内容、且该节点在入口已下发的绑定里时才发布（`EgressReady`），否则从订阅中撤下，不回退直出。
- 隧道流量取入口的计数，入口没有时取出口的；不计入任何用户。

**保存时校验**
- 节点和出口都必须是 PN 服务器，且出口不是节点自己的服务器。
- 隧道设置：协议必须是两者之一；出口地址必须是合法主机；REALITY 伪装站点必须合法。

### 第 3 期补充：命中记录出口与 sing-box 计量

- **sing-box 计量**：sing-box 服务器也统计转发与隧道的流量（转发、隧道的入口与出口各自计数），按计数器 epoch 处理重置；没有 Xray 时的“只跳过、不计量”不再成立。
- **命中记录出口**：PSP 只在四个条件同时成立时给策略置 `AuditEgress`——该 agent 声明了能力 `audit.hits.egress.v1`、编译引擎是 Xray、该服务器有出口绑定（编译输入的 `Egress` 非空）、记录没有关闭（协议校验拒绝“记录关闭却带出口标志”）。没有隧道的服务器和 sing-box 服务器收到的策略与摘要和以前逐字节相同；能力进入编译缓存键，能力变化会重新编译；回退到最近已知良好策略时标志只降不升。策略带该标志时：策略带 `AuditEgress` 标志时，入口给每条命中附上它经过的隧道（`AuditHit.Egress`，空表示从本服务器直出）。标志只在 Xray 上生效；拦截规则也只在这个标志下按隧道拆分（每条隧道一份副本），不带标志时拦截规则不拆分，与以前字节相同。
- 入库（`destaudit`）按链路号一次查出 `{入口, 出口}`：链路不存在、入口不是上报的服务器、或 agent 没声明 `audit.hits.egress.v1` 却带了出口，这条命中丢弃并计入丢弃类型 `egress_unknown`（指标 `hits_egress_unknown`，计入命中记录的 `dropped_in_range`）；查询失败按其他数据库错误处理，整批作废。链路从不删除、入口出口永不改变，所以结果可信。
- `dest_hits` 增加 `egress_panel_id`（0 = 从本服务器直出，也是已有行的值），列入主键，并有索引 `(egress_panel_id, hour_ms)`。升级时由 4.2 迁移重建表（见 `schema_upgrade_v4_2.go`）。管理接口 `GET /dest/hits` 接受 `exit_panel_id`（0 合法，不带表示不筛选）和 `group_by=exit`。`exit_panel_id` 只出现在未分组的行和 `group_by=exit` 的行上，`site`、`user`、`policy` 分组的行不带它（0 会被误读成“直出”）。

## 8. 规则（不变量）

1. 用户流量只在身份终结的那一跳计配额，另一跳记为链路流量。
2. 托管线路只在中转服务器确认当前转发后发布；隧道节点只在两侧都确认当前隧道后发布。失效时撤下，不回退直连或直出。
3. 转发和隧道入站不进入策略路由，只去固定去向。
4. 没有托管线路和隧道的服务器，配置字节、策略和编译产物与以前相同。

## 9. 来源 IP

透传时 B 只看到 A，基于 IP 的限制对经此线路的连接不生效，界面已标明。

**保留来源推迟到后续阶段（原定第 3 期）。** 现在基于 IP 的限制只观察、不执行（`IPShadow`），保留来源也不会让任何限制真正生效，所以先不做。

可选的“保留来源”（后续阶段）：仅两端都是 Xray 时可用，默认关闭，B 为该线路单独开影子端口接收 PROXY 头。依据是以下实测结论：

- sing-box 已移除 PROXY 协议，而且 `check` 能通过、启动才失败；
- 开启后同一端口上的直连会断；
- PROXY 头可被持有凭据的人伪造。

## 10. 多跳（预留）

`境内入口 → 境外中转 → 落地` 暂不支持，第 2 期的隧道结构为它预留位置，启用时需要成环检测和跳数上限。

## 11. 分期

1. **透传**（已实现）。
2. **隧道**（已实现）：两种隧道协议，加按出口的策略编译。
3. **审计出口维度 + sing-box 计量**（已实现）：命中记录出口服务器（`AuditEgress`，仅 Xray）；sing-box 转发与隧道也计量。
4. 透传保留来源（原第 3 期，推迟：IP 限制目前只观察、不执行）。
5. 链路质量自测、按目标分流、多跳、按线路设流量倍率。

发布顺序：Protocol 打标签 → Node 换正式依赖并发布 → PSP 换正式依赖。

## 12. 链路质量自测与压缩同步（4.3，开发分支）

**自测（`transit.probe.v1`）**

- 只向声明了该能力、且持有出口链路（`LinksOut`）或转发的服务器下发 `Transit.Probe`；没有声明的 agent 收到的配置与以前逐字节相同。
- 设置（管理员，`GET/PUT /api/admin/transit/probe-settings`）：开关（默认开）、间隔（60 秒，30–3600）、超时（5000 毫秒，500–10000）、探测地址（默认 `https://www.gstatic.com/generate_204`，http/https，端口 1–65535；**留空表示只测传输**：不经隧道抓取，不下发 `link_url`，没有 e2e 结果，芯片显示传输的数字）、撤下开关（默认关）、连续失败 N 次撤下（3）、连续正常 N 次恢复（3）。越界一律拒绝，不静默修正。
- 转发探测方法：默认 `tcp`；落地监听是纯 UDP（Hysteria2、TUIC）时用 `quic`；转发是 SNI 前置路由的目标时用 `tls`（前置功能到位后接入，入口在 `linkprobe.Method`）。
- 入库只收下发配置里的对象，且只收对的一侧：`LinksOut` 的 `e2e`／`transport`、转发的 `forward`；其余丢弃。状态表 `transit_probe_state`。
- 一个窗口：全部失败（且至少 3 次尝试）为 `down`，失败率不低于 20% 为 `degraded`，其余 `ok`；没有尝试或结果过期（超过 3 个上报间隔，取探测间隔与全量上报周期中较大者）为 `unknown`。
- 撤下：只在撤下开关打开时，连续 N 个 `down` 窗口置位、连续 M 个 `ok` 窗口清除。只数**新**窗口：内容（尝试、失败、RTT、最近成功、最近错误）变了算新窗口；内容不变（一直中断的链路每次都一样）则隔一个探测间隔才算一个。重复上报（同一 agent 时间戳且内容相同）整条忽略，agent 时钟回拨或跳到未来不会卡住状态。结果过期后整段历史作废，从新窗口重新判断；`unknown` 永不撤下并清除标记。关掉探测或撤下开关会立即清除所有撤下标记，读取时也只在开关打开时才认标记。被撤下的托管线路（`RelayLine.Publishable()`）或隧道节点（默认出口的链路，`withoutUnreadyEgress`）从订阅中去掉，永不回退直连。`health.go` 不变。
- 用户页 `relay_statuses` 只带粗略质量（ok／degraded／down）和中位 RTT。

**压缩同步（`sync.gzip.v1`）**

- `/v1/node/sync` 只接受声明过该能力的 agent 的 gzip 请求（其余带 `Content-Encoding` 的请求为 415）；线上 16 MiB、解压后 64 MiB，先读完线上字节（受 16 MiB 限制），再取解压槽，只在解压时占用；解压并发由信号量限制为 4，同一 agent 同时只解一份；等不到槽返回 503（带 `Retry-After`，agent 保持状态、下次轮询重发）。对声明了该能力的 agent，所有响应带 `Vary: Accept-Encoding`。指标：`psp_node_sync_gzip_refused_total`（415）、`psp_node_sync_decode_busy_total`（503）、`psp_node_sync_gzip_bytes_total`。
- 对声明了该能力的 agent，每个 2xx 响应带 `Accept-Encoding: gzip`；请求带 `Accept-Encoding: gzip` 时响应也压缩。没有该能力的 agent 行为不变。

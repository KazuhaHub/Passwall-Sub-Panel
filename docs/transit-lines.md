# 托管中转：PN 服务器之间的中转线路

> 状态：**提案**（2026-11-16）。只针对 Passwall Node（`PanelKind = psp`），不考虑第三方后端。

## 1. 目标

`用户 → A → B → 目标`，A、B 都是 PN，转发由 PSP 下发和管理。一台服务器可以只做中转、只做落地或两者都做，**不设角色字段**，由线路的引用关系推出来。

## 2. 两种方式

| | 透传 | 隧道 |
|---|---|---|
| 链路 | A 原样转发到 B 的用户入站 | A 解开用户协议，经 A—B 隧道从 B 出口 |
| 身份、计费、审计在 | B | A（但按 B 的规则，见 §4） |
| A 持有用户凭据 | 否 | 是 |
| 用户看到的协议 | B 的 | A 的 |
| 隧道协议 | 无 | 每条链路可选：SS-2022（不过墙）／VLESS+REALITY（过墙） |

## 3. 场景

| A 的位置 | A→B | 推荐 |
|---|---|---|
| 境外 | 境外互通 | A 可信时用隧道（SS-2022），否则用透传 |
| 境内 | 专线 | 透传 |
| 境内 | 公网过墙 | 透传（B 自己的协议负责抗封锁）；要用隧道必须选 VLESS+REALITY |

境内入口机：默认不允许终结用户协议（服务器开关 `allow_terminate`）；入口端口可自定义（NAT 机）；A 拨 B 的地址可单独填（专线内网、IPv6）。

## 4. 访问策略：跟着出口走

**一条连接适用它出口服务器的规则。**

- B 禁止 X：直连 B、经 A 透传、经 A 隧道，都禁止。
- A 禁止 X，B 不禁止：直连 A 禁止；经 A 到 B 的连接不禁止。

实现：

- 透传：执法本来就在 B，不用改。
- 隧道：在 A 上编译策略时，按出口给规则加入站限定。范围包含 B 的策略只作用于 A 上“出口 = B”的入站；范围包含 A 的策略只作用于 A 上本机出口的入站；全局策略作用于全部。协议里 `DestinationRule.Inbounds` 已经能表达这件事，**策略部分不需要改协议**。
- 审计行记录出口服务器。按出口服务器的采集设置在面板入库时过滤：A 上的 `Collect` 取各出口里最高的那一级，入库时丢掉出口服务器没开采集的那部分。

## 5. 改动概要

**Protocol**：新增能力 `transit.v1`、`transit.source.v1`、`audit.egress.v1`；`ConfigBody.Transit`（`omitempty`，没有线路时字节不变），包含透传入口、影子入口、隧道入站／出站、入站→出口绑定；上报 `TransitCounters`；新键类型 `TransitKey`（`fwd_`／`shd_`／`lnk_`），不复用 `ListenerKey`。

**Node**：

- 透传：Xray 用 `dokodemo-door`，sing-box 用 `direct` 加 override。
- 隧道：两种内核都用 SS 或 VLESS 出入站。
- 策略编译里“放行 = `direct`”改成“放行 = 该入站的出口”。只有一个出口时，编译结果与今天逐字节相同。

**PSP**：

- 新表 `transit_forwards`（透传线路）、`transit_links`（A→B 链路）、`transit_traffic_hourly`。
- 新列 `nodes.egress_panel_id`、`xui_panels.transit_port`。
- 发布顺序：建立时先出口后入口，拆除时反过来，两端都已应用才进订阅。
- 旧“中转线路”冻结，改称“外部入口”，只给 CDN 和第三方转发机用。

## 6. 规则（不变量）

1. 用户流量只在身份终结的那一跳计配额，另一跳记为链路流量。
2. 出口不可达时失败，不回退到本机出口；落地失效时线路撤下，不回退直连。
3. 隧道入站和透传入口不进入策略路由，只去固定去向。
4. 链路密钥和影子端口不出现在订阅、DTO、日志里。

## 7. 来源 IP

- 透传默认 B 只看到 A：入口地址并入现有基础设施地址集合，IP 相关限制对经此线路的连接不生效，界面标明。
- 可选“保留来源”（仅两端都是 Xray，默认关）：B 为该线路开一个单独的影子端口接收 PROXY 头。

实测结论：

- sing-box 已移除 PROXY 协议，而且 `check` 能通过、启动才失败。
- 开启 PROXY 后，同一端口上的直连会断。
- PROXY 头可以被持有凭据的人伪造。

所以影子端口要单独开，并且文档给出“只放行 A”的防火墙示例。

## 8. 多跳（预留，v1 不实现）

`境内入口 → 境外中转 → 落地`。现在只把位置留出来，v1 校验一律拒绝：

- 协议：`EgressBinding` 的来源可以是入站，也可以是某条链路的隧道入站（v1 只接受入站）。
- PSP：`transit_links.next_link_id`（v1 必须为空）。启用时要做成环检测，并限制跳数。
- 透传的目标仍然只能是用户节点。多跳透传等价于多次转发，用户侧不感知，以后按需开放。

## 9. 分期

1. **透传**（不保留来源）：覆盖大多数境内入口场景，先做。
2. **隧道**：两种隧道协议，加上按出口的策略编译。
3. **审计出口维度**，以及透传保留来源。
4. 链路质量自测、按目标分流、多跳。

每期按 Protocol → Node → PSP 的顺序发布。
